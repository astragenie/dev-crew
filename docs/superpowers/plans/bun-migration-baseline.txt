CLASS A: node:test Compat Blocker — Nested test() not implemented
=================================================================
Count: 108 test files AFFECTED
Issue: Bun's node:test compat layer raises NotImplementedError when test() is called at
  top-level file scope. GitHub Bun issue: oven-sh/bun#5090
  Error message: "test() inside another test() is not yet implemented in Bun.
  Use `bun:test` in the interim."

Root cause: Test files use flat test() calls with NO describe() wrapper:
  Example (artifact-naming.test.mts lines 1, 15, 20, 25, ...):
    import test from "node:test";
    test("...first test...", () => { ... });
    test("...second test...", () => { ... });

The Node.js test runner allows this pattern (flat call-site tests). Bun's compat
layer rejects it, requiring either:
  a) Switch affected files to `import test from "bun:test"`, OR
  b) Wrap all tests in describe("...", () => { test(...); test(...); })

Task 3 Scope Determination
==========================

Recommendation: Large-scale codemod required, but feasible.

Option A: Codemods all 108 files from node:test to bun:test
  Scope: sed/codemods to replace import statements per file
  Effort: ~2-3 hours including verification
  Advantages: Minimal test-logic changes; tests stay identical semantically
  Disadvantages: Locks tests to Bun; no longer Node.js compatible

Option B: Wrap all tests in describe() blocks (keep node:test compatible)
  Scope: Wrap every test file's body in describe("...", () => { ... })
  Effort: Higher; requires structural AST changes per file
  Advantages: Tests remain Node.js compatible; Bun can run them later
              when nested test() support lands in oven-sh/bun#5090
  Disadvantages: Adds boilerplate; changes test structure significantly

DECISION (from spec Slice 1): Option A — switch to bun:test.
  Rationale: Bun is a hard requirement in Slice 2. Tests lock to Bun is acceptable.
  Fallback: If oven-sh/bun#5090 lands before Slice 2, revert to node:test.

Culprit file: slice-complete.test.mts
  - Hangs consistently when run in isolation (verified 2 runs, both hanged)
  - 30-second timeout confirms it's a hard hang, not slowness

Root cause: src/scripts/lib/slice-linker/complete-slice.mts:741-753
  Function checkBranchExists() uses:
    ```
    const execFile = promisify(execFileCb);
    await execFile("git", ["-C", repoPath, "rev-parse", "--verify", branchName], {
      timeout: 30_000
    });
    ```

  Problem:
    1. Test tmpRepo() creates a temporary directory with .claude/ folder BUT
       does NOT initialize it as a git repository
    2. On Windows, git hangs when trying to locate .git in a non-git directory,
       even with a timeout set on execFile (the timeout only covers the git
       process execution, not the initial git discovery phase which walks
       parent directories)
    3. Parallel test execution exacerbates this: multiple bun worker threads
       simultaneously execute git on non-git tmpdirs, causing file lock
       contention and indefinite blocking

Solution path (Reliability T2):
  - Add explicit git repo initialization to tmpRepo() test fixture, OR
  - Add explicit timeout + Promise.race() at call-site to interrupt git discovery, OR
  - Add afterAll cleanup hook to prevent worktree-path pollution across tests
