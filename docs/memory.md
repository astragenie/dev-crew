# runner-plugin — Memory (durable-facts index)

Volatile, dated facts and detail that used to bloat `CLAUDE.md`. **Supersede
entries by editing them in place** (update the date + content) rather than
appending forever. For full history see `.claude/artifacts/{crew,loop}/`,
`CHANGELOG.md`, and git log.

`CLAUDE.md` keeps only the clause headings + a one-line pointer per topic (the
`<!-- clause: X -->` markers are a machine-read contract — see "Load-bearing
CLAUDE.md contracts" below); this file carries the depth.

## Load-bearing CLAUDE.md contracts (do not break)

Verified 2026-07-21 by grepping every script that reads `CLAUDE.md`
programmatically:

- **Clause-id registry** (`src/scripts/lib/clause-registry.mts`) reads
  `CLAUDE.md` for `<!-- clause: <id> -->` markers immediately after an `## `
  heading. `src/scripts/validate-decline-citations.mts` requires every P4
  FEAT's `declined_per` field to cite one of these ids. **Never delete a
  clause marker** without checking `declined_per` usage first (currently
  live-cited: `backlog-discipline`, `repo-conventions` — see
  `FEAT-078/090/092/175` in `.claude/artifacts/loop/backlog/done/`).
- **CI-gate count** (`src/scripts/generate-metrics-band.mts::countCiGates`)
  counts top-level `N. ` lines under `CLAUDE.md`'s `## CI gates` heading,
  until the next `## `. The README metrics band's "CI gates enforced" number
  is generated from this count and gated by CI (`--check` mode). Full detail
  per gate lives in `docs/ci-gates.md`; **the numbered list itself must stay
  in CLAUDE.md** with the same count and order as that file.
- **Agent-ref sweep** (`src/scripts/validate-agent-refs.mts`, `SCAN_FILES =
  ["CLAUDE.md"]`) flags any `crew:<name>` / `runner:<name>` token in
  CLAUDE.md that doesn't resolve to a real agent/command/skill. Don't
  introduce a new dispatch-token reference without confirming it resolves.
- **Marker block** (`<!-- runner:start -->`...`<!-- runner:end -->`) is
  regenerated by `/runner:install` from `templates/claude-md-hard-rules.md`
  — never hand-edit its content; edit `.claude/loop.json` and re-run install.

## Marathon checkpoint

`checkMarathonCheckpoint` counts grade files written after the newest
retrospective. `loop.marathonCheckpointEvery` in `.claude/loop.json`
(default **4**, per the AgentOps coherent-arc rule):

- `>= every` closes → advisory `marathon_checkpoint_due`, loop continues.
- `>= 2 * every` closes → hard stop `marathon_checkpoint_required` +
  `marathon-checkpoint` blocker until a retrospective lands under
  `.claude/artifacts/loop/retrospectives/`.
- `marathonCheckpointEvery: 0` or negative falls back to the default rather
  than disabling — true opt-out needs the snapshot consumer removed or
  continuous `/runner:retrospective` runs.

## Backlog discipline — command history

- `/runner:intake` (PM scoring + architect classification in one call) is
  the recommended entry point; it replaced the two-step
  `/runner:triage` + `/runner:backlog-enrich` sequence (`backlog-enrich`
  removed as a standalone command in v0.53, stub redirects to
  `/runner:intake`; see `src/tests/deleted-skills-stub.test.mts`).
- `--deep` (or automatic P0/P1 trigger) makes the PM draft Given-When-Then
  ACs inline in the same response (FEAT-277) — no separate
  `runner:spec-writer` fanout, no standalone `/runner:retriage` (both
  removed v0.53).
- **FEAT-218 Phase 2 / DEC-069 (2026-07-06)**: `scripts/presets/*.json` are
  install-time templates only — `resolveConfig` no longer reads or merges
  preset files at runtime; an unconfigured repo errors instead of silently
  defaulting to `dotnet-python`.
- `surface`/`stack` per-FEAT classification was dropped on
  feat/preset-skill-activation — the resolver's own preset lookup is now
  the sole source (`docs/upstream-requests/archive/2026-06-07-hero-crew-orchestrate-slice-surface-stack-routing.md`
  is superseded).
- **ARCHITECT GATE (`arch_*` FEAT frontmatter fields, DEC-075, additive
  schema v2)**: `arch_status` (`gate_in_progress`|`approved`|`deferred_design`),
  `arch_attempt` (rejection counter, cap `MAX_ARCH_GATE_ATTEMPTS = 2`),
  `arch_defer_reason`, `arch_review` (normalized `approved`|`rejected`),
  `arch_risk` (risk-flag array, falls back to `objections` when
  `riskFlags` omitted). `isArchGateActive()` blocks `pm-apply`'s
  `--include-triaged` re-triage pass from clobbering a FEAT the gate is
  mid-cycle on or has deferred; does not gate `applyPmRescope` (a rescope
  during `gate_in_progress` is the write the gate itself requested). Full
  design record: `.claude/artifacts/loop/decisions/DEC-075.md`.

## Orchestrator mode — legacy history

`config.loop.orchestratorMode` in `.claude/loop.json` selects `"slice-build"`
(default, per-tag `crew:<variant>-dev` subagent dispatch) or
`"orchestrate-slice"` (`/crew:orchestrate-slice`, sequential from main
thread). Legacy modes `"lead"` and `"direct-builder"` were removed in v0.43 /
FEAT-191 — `lead` suffered persistent specialist-pause across
SLICE-97/98/99/101/102/103/104; `direct-builder` was a strict subset of
`slice-build` with `tags: []`. Operators with stale config silently fall
back to `slice-build`. If the upstream lead-pause issue is fixed in
`dev-team`, `lead` could be revived as a separate FEAT.

## Reviewer ladder — current setting

This repo runs `reviewers.ladder: ["A"]` (single reviewer, lighter gate) with
**no post-builder validator** — the close-time validation gate is satisfied
by the reviewer's approval badge (`loop.validation.satisfiedByReview: true`,
see `deriveValidationGate` in `src/scripts/lib/validation-gate.mts`).
Behavior/test validation is delegated to the CI test gate instead. A
`multidim` three-dimension preset (FEAT-079/SLICE-82) was built for one
slice and left no surviving code (`grep -rn multidim src/scripts` → zero
matches) — not a general opt-in; re-enabling it means re-implementing, not
flipping a switch.
