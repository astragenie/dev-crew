# runner-plugin — Memory (durable-facts index)

Volatile, dated facts and detail that used to bloat `CLAUDE.md`. **Supersede
entries by editing them in place** (update the date + content) rather than
appending forever. For full history see `.claude/artifacts/{crew,loop}/`,
`CHANGELOG.md`, and git log.

`CLAUDE.md` keeps only the clause headings + a one-line pointer per topic (the
`<!-- clause: X -->` markers are a machine-read contract — see "Load-bearing
CLAUDE.md contracts" below); this file carries the depth.

## Load-bearing CLAUDE.md contracts (do not break)

Verified 2026-07-21 by grepping every script that reads `CLAUDE.md`
programmatically:

- **Clause-id registry** (`src/scripts/lib/clause-registry.mts`) reads
  `CLAUDE.md` for `<!-- clause: <id> -->` markers immediately after an `## `
  heading. `src/scripts/validate-decline-citations.mts` requires every P4
  FEAT's `declined_per` field to cite one of these ids. **Never delete a
  clause marker** without checking `declined_per` usage first (currently
  live-cited: `backlog-discipline`, `repo-conventions` — see
  `FEAT-078/090/092/175` in `.claude/artifacts/loop/backlog/done/`).
- **CI-gate count** (`src/scripts/generate-metrics-band.mts::countCiGates`)
  counts top-level `N. ` lines under `CLAUDE.md`'s `## CI gates` heading,
  until the next `## `. The README metrics band's "CI gates enforced" number
  is generated from this count and gated by CI (`--check` mode). Full detail
  per gate lives in `docs/ci-gates.md`; **the numbered list itself must stay
  in CLAUDE.md** with the same count and order as that file.
- **Agent-ref sweep** (`src/scripts/validate-agent-refs.mts`, `SCAN_FILES =
  ["CLAUDE.md"]`) flags any `crew:<name>` / `runner:<name>` token in
  CLAUDE.md that doesn't resolve to a real agent/command/skill. Don't
  introduce a new dispatch-token reference without confirming it resolves.
- **Plugin hooks file lives at `hooks/hooks.json` at the plugin root — the
  only path Claude Code's plugin loader discovers.** Found 2026-11-05 by a
  live two-plugin marker test (`.claude/artifacts/crew/validations/20261105T223500Z-validation-plugin-hooks-json-discovery.md`,
  CLI 2.1.270): a `hooks.json` at `.claude-plugin/hooks/hooks.json` never
  loads, regardless of content. devcrew shipped all 38 hook entries there
  through v1.1.0, so **no devcrew hook ran for any consumer** (gate guard,
  pre-push gate, guard-feat-dispatch, telemetry) — this repo's own
  `.claude/settings.json` dogfood hooks (12 entries) masked it locally.
  Fixed in FEAT-033/SLICE-46 (2026-11-06): `git mv` to `hooks/hooks.json`,
  no manifest `hooks` key added at the old location (either would
  double-fire). `src/scripts/validate-repo-boundary.mts`'s
  `HOOKS_JSON_REL` constant and `docs/planning/hooksjson-crew-path-inventory.json`
  both point at the new path now; `src/tests/install/hooks-discovery.test.mts`
  guards against regression. Re-check on a CLI >= 2.1.295 before trusting
  this is still version-stable — discovery rules may change (noted as an
  open risk in the validation artifact).
- **Two marker blocks, two installers, both preserved byte-identical by
  SLICE-25's docs merge:** `<!-- crew:start -->`...`<!-- crew:end -->` is
  regenerated by `/crew:install` from the crew plugin's own template
  (includes `.claude/crew/constitution.md`); `<!-- runner:start -->`...
  `<!-- runner:end -->` is regenerated by `/runner:install` from
  `templates/claude-md-hard-rules.md`. Never hand-edit either block's
  content; edit `.claude/crew.json` / `.claude/loop.json` and re-run the
  matching install command. Post-cutover (FEAT-006) these collapse to a
  single `/devcrew:install`-owned block — not yet done as of this entry.

## CI gates

Full per-gate rationale: `docs/ci-gates.md`.

**Gate 41 is red by design on `fix/audit-2026-11` (2026-11-06).**
`src/tests/install/consumer-smoke.test.mts` (FEAT-022 / SLICE-47) runs every
shipped hook and CLI entry from a `node_modules`-free consumer copy and stays
RED while its `EXPECTED_FAIL` ratchet holds entries — 49 at SLICE-47, 41 as
of FEAT-026/SLICE-52 (every HOOK entry now passes from the committed
`dist/` bundles; the remaining 41 are CLI entries sourced from
`commands/*.md`/`agents/*.md` literal invocations, which still resolve
`@astragenie/*`/`zod`/`yaml` from `node_modules` until the serial W2.5
path-rewrite lands). Do not quarantine it: the same ratchet fails loudly
when a listed entry starts passing or an unlisted one breaks. The
merge-blocking `gate` job depends only on `fast-gate`, so this does not
block merges. Verified 2026-11-06 (validation artifact
`20261106T040313Z-validation-result-slice-47-…`): the failure is the designed
assertion only, and the staged copy contains no `node_modules` at any depth.

**FEAT-026 alternative rejected (dist/ bundling vs. auto-installed deps).**
Claude Code auto-installs a plugin-root `dependencies` block for
marketplace installs (see Claude Code's `loading.md`), which would have let
hooks/CLI entries resolve `node_modules` normally with zero bundling work.
Rejected: devcrew is ineligible for that path — the root `bun.lock`
declares workspaces, `crew/`'s own `package.json` (its `zod`/`yaml` deps) is
never installed by that mechanism, and `@astragenie/*` needs registry auth
at install time regardless. `Bun.build({target:"bun", external:
["@opentelemetry/*","@aws-sdk/*"]})` bundling was chosen instead — no
network, no auth, no install step; `src/scripts/build-dist.mts` is the
build/`--check` tool, `.bun-version` pins the Bun build used.

**FEAT-026 dist-path entry-recovery (`build-dist.mts`).** Once
`hooks/hooks.json` is migrated so every `bun` command points at
`dist/hooks/<name>.js` (this FEAT's own deliverable), a naive "every `bun
".../<path>.mts"` command in hooks.json" entry-discovery regex finds zero
hook sources post-migration — a *subsequent* `bun run build:dist` then
deletes every previously-built `dist/hooks/*.js` file, because `build()`
rm -rf's `dist/` before rebuilding from whatever `resolveEntries()` found
(hit live during SLICE-52: a resumed builder's working tree showed a
54k-line dist/ deletion after it ran `build:dist` post-hooks.json-edit).
Fix: `collectHookEntries` now also matches the post-migration
`dist/hooks/<base>.js` form and recovers the `.mts` source by basename
lookup across `hooks/` and `crew/hooks/` (erroring loudly on zero or 2+
matches) — `hooks/hooks.json` stays the single enumeration of hook entries
(DEC-040) in both the pre- and post-migration shape.

## Marathon checkpoint

`checkMarathonCheckpoint` counts grade files written after the newest
retrospective. `loop.marathonCheckpointEvery` in `.claude/loop.json`
(default **4**, per the AgentOps coherent-arc rule):

- `>= every` closes → advisory `marathon_checkpoint_due`, loop continues.
- `>= 2 * every` closes → hard stop `marathon_checkpoint_required` +
  `marathon-checkpoint` blocker until a retrospective lands under
  `.claude/artifacts/loop/retrospectives/`.
- `marathonCheckpointEvery: 0` or negative falls back to the default rather
  than disabling — true opt-out needs the snapshot consumer removed or
  continuous `/devcrew:retrospective` runs.

## Backlog discipline — command history

- `/devcrew:intake` (PM scoring + architect classification in one call) is
  the recommended entry point; it replaced the two-step
  `/devcrew:triage` + `/runner:backlog-enrich` sequence (`backlog-enrich`
  removed as a standalone command in v0.53, stub redirects to
  `/devcrew:intake`; see `src/tests/deleted-skills-stub.test.mts`).
- `--deep` (or automatic P0/P1 trigger) makes the PM draft Given-When-Then
  ACs inline in the same response (FEAT-277) — no separate
  `runner:spec-writer` fanout, no standalone `/runner:retriage` (both
  removed v0.53).
- **FEAT-218 Phase 2 / DEC-069 (2026-07-06)**: `scripts/presets/*.json` are
  install-time templates only — `resolveConfig` no longer reads or merges
  preset files at runtime; an unconfigured repo errors instead of silently
  defaulting to `dotnet-python`.
- `surface`/`stack` per-FEAT classification was dropped on
  feat/preset-skill-activation — the resolver's own preset lookup is now
  the sole source (`docs/upstream-requests/archive/2026-06-07-hero-crew-orchestrate-slice-surface-stack-routing.md`
  is superseded).
- **ARCHITECT GATE (`arch_*` FEAT frontmatter fields, DEC-075, additive
  schema v2)**: `arch_status` (`gate_in_progress`|`approved`|`deferred_design`),
  `arch_attempt` (rejection counter, cap `MAX_ARCH_GATE_ATTEMPTS = 2`),
  `arch_defer_reason`, `arch_review` (normalized `approved`|`rejected`),
  `arch_risk` (risk-flag array, falls back to `objections` when
  `riskFlags` omitted). `isArchGateActive()` blocks `pm-apply`'s
  `--include-triaged` re-triage pass from clobbering a FEAT the gate is
  mid-cycle on or has deferred; does not gate `applyPmRescope` (a rescope
  during `gate_in_progress` is the write the gate itself requested). Full
  design record: `.claude/artifacts/loop/decisions/DEC-075.md`.

## Orchestrator mode — legacy history

`config.loop.orchestratorMode` in `.claude/loop.json` selects `"slice-build"`
(default, per-tag `crew:<variant>-dev` subagent dispatch) or
`"orchestrate-slice"` (`/devcrew:orchestrate-slice`, sequential from main
thread). Legacy modes `"lead"` and `"direct-builder"` were removed in v0.43 /
FEAT-191 — `lead` suffered persistent specialist-pause across
SLICE-97/98/99/101/102/103/104; `direct-builder` was a strict subset of
`slice-build` with `tags: []`. Operators with stale config silently fall
back to `slice-build`. If the upstream lead-pause issue is fixed in
`dev-team`, `lead` could be revived as a separate FEAT.
