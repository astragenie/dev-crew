# DEC-047: Builder report contract is a marker-first final message; no pre-review publish, no SendMessage

## Context

`agents/fullstack-dev.md:213-218` (and `backend-dev`, `frontend-dev`,
`aiplugin-dev`) mandated push + draft PR + `node ./scripts/report-to-pr.ts`
before reporting — bypassing the dispatcher's explicit-approval ship
boundary (audit #7; Codex #22, #6; architect OBJ-4; reviewer BLOCKER 1) —
and contradicted each other on the reporting channel (PR comment vs
`SendMessage` vs handoff). Two live hooks key on a LINE-START status
marker: `crew/scripts/lib/subagent-return/incomplete-detector.mts:19`
(`/^(DONE|BLOCKED|HELP|HELP-REQUEST|IN-PROGRESS)\s*:/im`) and
`crew/hooks/lib/subagent-gate-guard.mts:51` (`/^DONE\s*:/im`) — either
hook would have gone dark had the new contract started the block with a
different word. DEC-038 (SLICE-43) introduced a SubagentStop receipt
schema and a `hooks/report-gate.mjs` lane that also expects a
`SendMessage` tool_use call as the fulfillment signal for a detected
"report-back contract" (a `SendMessage ... main` phrase in the dispatch
prompt) — that lane is opt-in (`features["report-gate"].enabled`, unset
in this repo's `.claude/loop.json`) and was never turned on here, but a
future repo that did enable it would false-block the four builders below
once they stop calling `SendMessage` entirely.

## Decision

The four builder-tier agents (`fullstack-dev`, `backend-dev`,
`frontend-dev`, `aiplugin-dev`) return their completion report as the
literal final message of their turn: 4 lines, marker first —
`DONE:`/`BLOCKED:`/`HELP:`/`IN-PROGRESS:` on line 1, then `FILES:`,
`TESTS:`, `NEXT:`. No PR comment, no `gh pr create`, no `git push`, no
`SendMessage` call. The SubagentStop event (not a tool call) is the
delivery mechanism; the dispatcher reads `last_assistant_message`
directly. This supersedes DEC-038's `SendMessage`-based receipt-delivery
lane for these four agents specifically: `hooks/report-gate.mjs`'s
`SendMessage`-tool_use scan (the `REPORT_BACK_CONTRACT_RE` /
`hasSendMessageToolUse` fulfillment path) is retired in intent for the
marker-first builders and stays optional/off by default (documented
in-file; the opt-in `report-gate` feature flag is not set in this repo's
`loop.json`, so no runtime behavior changes here). The independent
receipt-lane-table write in that same file (AgentReceipt sighting via
`SendMessage`, FEAT-008/SLICE-43) is unaffected — it is additive and
never blocks, and remains valid for any agent that still uses
`SendMessage`. `crew/scripts/validate-agents.mts` gained two new rules
enforcing the new contract mechanically: `no-relative-script-path` (agent
prompts must invoke plugin scripts via
`bun "${CLAUDE_PLUGIN_ROOT}/crew/scripts/<name>.mts"`, never a relative
path) and `no-prereview-publish` (the four builders must never contain
`gh pr create` / `git push` outside a dedicated `## Ship` section, which
none of them have). The pre-existing `peer-dispatch` rule's "has `Agent`
tool" detection was also fixed in the same pass (Codex #6): an absent
`tools:` frontmatter field now defaults to "all tools" (which includes
`Agent`) unless `disallowedTools` names `Agent` — previously the rule only
fired when `tools:` explicitly listed `Agent`, which no allowlisted agent
declares, making the rule permanently inert.

## Consequences

### Positive

- One reporting channel, not three: the marker-first block is both the
  human-readable report and the two hooks' detection signal, so there is
  nothing left to go out of sync between agent prompts.
- Builders can no longer push or open a PR before the dispatcher's review
  gate — closes the ship-boundary bypass audit #7/Codex #22 flagged.
- `incomplete-detector` and `subagent-gate-guard` needed zero logic
  changes — both already match on a line-start `DONE:`/etc. marker, and
  the new block satisfies that unchanged (see fixtures added in
  `crew/tests/incomplete-detector.test.mts` and
  `crew/tests/subagent-gate-guard.test.mts`).
- The `peer-dispatch` rule fix gives real coverage for the first time on
  `fullstack-dev`, `backend-dev`, `frontend-dev` (all three now carry an
  explicit `max N peer dispatches` budget line where none existed before).

### Negative

- `hooks/report-gate.mjs`'s block path (if ever enabled) would still
  produce a stale "Call SendMessage(to: main, ...)" remediation message
  for one of these four agents — the block mechanism itself was left
  untouched (doc/flag-only per FEAT-028 scope), so a repo that opts into
  `report-gate` AND dispatches these builders would see a misleading
  instruction. Mitigated by: the feature defaults off, this repo keeps it
  off, and the file's header comment now documents the gap explicitly so
  a future operator doesn't enable it blind.

### Neutral

- `hooks/report-gate.mjs`'s receipt-lane-table write path (distinct from
  the block path) is untouched and still valid for any agent still using
  `SendMessage` with an embedded AgentReceipt JSON blob.

## Alternatives considered

- **Keep `SendMessage` as the fast-path backstop, drop only the PR
  steps** — rejected: this was the prior (pre-FEAT-028) state and is
  exactly the three-way contradiction (PR comment vs `SendMessage` vs
  handoff) the audit flagged; keeping any second channel reintroduces the
  "report dies with a truncated agent" failure mode whenever the agent
  stops before calling the tool.
- **Rip out `hooks/report-gate.mjs`'s block path entirely** — rejected:
  out of scope (FEAT-028 scope is agent prompts + `validate-agents.mts` +
  this decision record; `report-gate.mjs` is "doc/flag only"), and the
  path is already inert by default in every repo that hasn't explicitly
  opted in.
