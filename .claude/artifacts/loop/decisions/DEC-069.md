# DEC-069: remove the preset runtime-merge layer, keep templates on disk

## Context

FEAT-218 asked to analyze the preset layer (`scripts/presets/*.json` +
`config-resolver.mts`'s deep-merge) and then eliminate it: 6 overlapping
files sitting under `.claude/loop.json`, with a resolver default
(`dotnet-python`) that is wrong for most repos. Phase 1
(`docs/research/2026-07-06-preset-removal.md`) enumerated every field, every
consumer, and what breaks if presets vanish outright — chiefly, a hardcoded
cross-plugin path coupling in dev-team's `orchestrate-slice.md` Step 2.5
(`--preset "${LOOP_ROOT}/scripts/presets/${PRESET_NAME}.json"`).

## Decision: **installer-time inlining + template demotion.** Accepted.

`scripts/presets/*.json` are **not deleted**. They become install-time-only
templates:

1. `/runner:install --preset X` is the only remaining reader of
   `scripts/presets/*.json`. It inlines the named template's full content
   (`loop.*`, `stack.*`, `reviewers`, `mandatoryDocs`, `productName`/
   `productDescription`, `stackDescription`, `skills`/`fe`/`be`, `roles.*`)
   directly into `.claude/loop.json` at scaffold time
   (`loop-installer.mts::installLoop`).
2. `config-resolver.mts::resolveConfig` no longer defaults to
   `"dotnet-python"` (AC-5) and no longer merges a preset at runtime. It has
   two modes: an explicit `options.preset` (the install-time scaffold path,
   unchanged deep-merge semantics) or the normal runtime path — reads
   `.claude/loop.json` directly, throws a clear
   `` Run `/runner:install --preset <name>` `` error if the file is missing.
   No silent wrong-stack fallback.
3. A first-time install (no existing `.claude/loop.json`) now requires
   `--preset` explicitly — `installLoop` pre-flight-checks this and errors
   before touching disk. Re-installing an already-configured repo may omit
   `--preset`; the existing (already self-contained) config is read as-is.
4. `preset-schema.mts::validatePreset` gained the validation Phase 1 found
   missing: `loop.*` (object), `stack.*` (stage shape `{cmd,args?,cwd?}` or
   null per stage, array for build/test), `reviewers.ladder` (`"A"`/`"B"`
   only), `mandatoryDocs` (string array), `productName`/`productDescription`/
   `stackDescription` (strings) — all optional, validated when present. Still
   invoked by `validate-manifests.mts::validateAllPresets` against the 6
   shipped template files; not wired into a new `.claude/loop.json` CI gate
   (out of scope for this slice — no AC requires it, and doing so half-baked
   risks failing already-installed repos across the org that predate this
   change).
5. `skill-resolver.mts::resolveSkills` is unchanged in shape (still
   `presetPath` + optional `overridePath` + `variant`). AC-4's golden test
   (`src/tests/skill-resolution-golden.test.mts`) proves resolved skills are
   byte-identical whether `presetPath` points at
   `scripts/presets/<name>.json` or at an installer-inlined
   `.claude/loop.json` — the payload contract dev-team depends on doesn't
   change.

## Deferred (tracked, not done here)

Repointing dev-team's `orchestrate-slice.md` Step 2.5 from
`scripts/presets/${PRESET_NAME}.json` to `.claude/loop.json` is a
cross-plugin change, out of scope for this (loop-only) slice. Filed as
`docs/upstream-requests/2026-07-06-crew-orchestrate-slice-preset-path.md`.
Until it lands, dev-team continues reading `scripts/presets/*.json` directly
— which still works today because those files remain on disk unchanged.

## Consequences

- **Known gap**: repos installed before this change whose `.claude/loop.json`
  is a thin override (relying on runtime preset merge for most fields, e.g.
  just `{"preset": "x"}` plus a couple of overrides) will see those
  preset-derived fields silently disappear on the next `resolveConfig` call
  post-upgrade (no merge). The safe path is re-running `/runner:install
  --preset <name>` to regenerate a self-contained config — the installer
  writes idempotently (only if missing), so an already-`.claude/loop.json`-
  bearing repo must delete-and-reinstall or hand-merge the missing fields.
  This repo's own `.claude/loop.json` was already self-contained
  (`stack`/`loop`/`reviewers`/`mandatoryDocs`/`skills` all present verbatim)
  and needed no migration.
- `--preset` survives as the install-time template selector (low-cost,
  matches the "pick the closest stack" onboarding UX); `/runner:list-presets`
  keeps working unchanged since it only enumerates template choices.
- `grep -rn "scripts/presets" src commands` after this change only matches
  `config-resolver.mts`'s scaffold-path loader/lister and doc prose — no
  runtime resolution path reads it (AC-2).
