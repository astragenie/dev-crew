# DEC-020: Dirty-tree check uses `-uno` (untracked-no) semantics

## Context

Strict `git status --porcelain` (no flag) treats untracked loop/crew state files as "dirty" and blocks worktree creation in normal slice flow. `-uno` ignores untracked, blocks only on staged or unstaged tracked-file changes. This matches git's own `worktree add` policy (which does not require any clean tree at all) but adds a loop-side safety net against cross-slice tracked changes.

- positive: still catches the genuine "operator has uncommitted source changes" case the FEAT was designed to gate
- negative: an unstaged modification to a tracked file in a subdirectory will block; operator must commit or stash. This is intentional but worth documenting.
