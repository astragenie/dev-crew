# DEC-019: Failure-atomicity invariant for slice-start worktree writes

## Context

When worktreeMode is on, slice-start writes worktreePath to TWO places (workflow-state + slice frontmatter). The contract treats this as atomic: both succeed or neither persists. If frontmatter write fails, state rolls back. If sliceFile is null at apply-time, throw BEFORE state write rather than silently writing a half-state.

- negative: orphan worktree risk when ensureSliceWorktree succeeds on disk before the null-sliceFile throw fires. Acceptable: operator sees the throw + can clean up manually. FEAT-061 may add automatic worktree-clean.
