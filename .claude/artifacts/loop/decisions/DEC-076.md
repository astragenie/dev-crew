# DEC-076: BacklogStore storage seam — feature/slice write consolidation, doctor.mts exception, failure-pivot regex port

## Context

FEAT-250 (tracker-provider migration Phase 1) introduces a single BacklogStore
module as the storage seam beneath the future TaskStoreProvider mirror layer.
Today, feature-lifecycle writes are already centralized in
`backlog-writer.mts` (11 callers, all routing through 4 exported functions —
verified by grep, no raw fs reach-through). Slice-lifecycle writes are not:
three call sites (`slice-linker/complete-slice.mts`, `slice-linker/
feature-lifecycle.mts` x2, `wave/failure-pivot.mts`) each perform their own
raw fs writes, and `failure-pivot.mts` additionally mutates frontmatter via a
hand-rolled regex rather than the shared `frontmatter.mjs` parser. Per the
architecture review (`.claude/artifacts/crew/reviews/
2026-07-09-tracker-provider-plan-review.md`, COND-A/COND-D), this DEC
resolves three decisions before SLICE-2/3/4 code: the BacklogStore interface
shape, the failure-pivot port-vs-exception call, and the doctor.mts
classification.

Full interface signatures and CI-guard sketch: see the design artifact
`.claude/artifacts/crew/runs/2026-07-10-backlogstore-design.md`.

## Decision

1. **New module `src/scripts/lib/backlog-store.mts`** becomes the sole
   direct-fs writer for backlog feature and slice lifecycle state.
   `backlog-writer.mts` keeps its existing exported names/signatures
   (`addFeature`, `updateFeatureFrontmatter`, `moveFeature`,
   `findFeatureById`) as re-exports of the moved function bodies — zero
   caller-file changes required for the 11 existing consumers. New
   `createSlice`, `updateSliceFrontmatter`, `moveSlice`, `listByState`,
   `getById` methods consolidate the 3 scattered slice write sites.
2. **`wave/failure-pivot.mts`'s hand-rolled frontmatter regex is ported** to
   `updateSliceFrontmatter`/`mergeFrontmatter`. The shared parser already
   supports the nested `last_failure:` mapping shape natively
   (`frontmatter.mts` `isPlainMapping`/`serializeFrontmatter`) — the regex
   duplicates existing capability rather than working around a gap. The
   port introduces one new convention: `pending_fix` deletion (currently
   done via regex removal on the escalating branch) is represented as
   `pending_fix: null` written through `mergeFrontmatter`'s set-only merge,
   with all readers of `pending_fix` updated to treat `null`/absent
   identically — verified as a contained, single-reader-group change at
   DEC time; SLICE-3 must re-verify against the live reader list.
3. **`doctor.mts` is a named CI-guard allowlist exception, not migrated
   onto BacklogStore.** Its reconciliation performs byte-preserving,
   cross-root moves (`applyFix`, `doctor.mts:139-238`) that are
   structurally incompatible with BacklogStore's single-root,
   frontmatter-merging lifecycle-transition model — forcing it through
   `moveFeature`/`moveSlice` would inject frontmatter mutation the function
   deliberately avoids to preserve audit-accurate loser/winner content.

## Consequences

### Positive
- Feature-side conversion (SLICE-2) is mechanical and low-risk: 11 callers
  need zero changes, because they never touch raw fs today.
- Slice-side consolidation (SLICE-3) closes an existing near-duplication
  (single-slice and multi-slice construction each inline their own
  `buildSliceContent` + write sequence today) as a side effect.
- The failure-pivot port removes a hand-rolled parser whose only advantage
  over the shared one was historical, not functional.

### Negative
- The `pending_fix: null`-as-delete convention is a new semantic contract
  every future reader of that field must respect; a reader added after this
  DEC that checks `"pending_fix" in frontmatter` rather than truthiness
  would silently break.
- `serializeFrontmatter`'s full-block re-serialization means the
  failure-pivot port normalizes any block-style array formatting elsewhere
  in a touched slice's frontmatter to inline-bracket style — a formatting
  change, not a correctness one, but it means the port's regression test
  must assert on parsed structure, not exact bytes (unlike AC-1's stricter
  bar for feature-side callers).

### Neutral
- doctor.mts remaining an allowlist exception means a future generalized
  "reconcile across roots" BacklogStore capability, if ever needed, is
  explicitly out of scope for this program.

## Alternatives considered

- **Doctor.mts migrated onto BacklogStore with a new `reconcile()` method.**
  Rejected: would require BacklogStore to support cross-root operations and
  byte-preserving (non-frontmatter-merging) writes, both outside Phase 1's
  storage-seam mandate — new scope, not consolidation.
- **failure-pivot.mts kept as a documented allowlist exception instead of
  porting.** Rejected: the shared parser already supports the exact nested
  mapping shape the regex hand-builds; keeping a second bespoke parser
  around has no remaining justification once that's established, and two
  parsers for the same file format is itself a latent-bug source.
