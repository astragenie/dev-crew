# DEC-023: Single resolveEffectiveCwd helper over per-subcommand inline state-read

## Context

Centralising the precedence chain (`--worktree` > `currentRun.worktreePath` > `--repo`) in a single helper keeps the contract testable in one place. Each subcommand becomes a thin caller. Alternative considered: duplicate the read in each handler — rejected because future changes (e.g. honoring a new flag) would need 6+ edits.

## Consequences

### Positive

- positive: 9 unit tests fully characterize the resolution logic; subcommands become uniformly worktree-aware via one call.
- positive: a future `crew:fix` flow can also call `resolveEffectiveCwd` and inherit identical semantics.
- negative: every affected subcommand pays an extra dynamic `import()` per invocation; cost is negligible (Node ESM cache) but the call sites multiply imports of `effective-cwd.mjs`.
