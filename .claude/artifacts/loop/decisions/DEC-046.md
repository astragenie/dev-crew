# DEC-046: Validation-skip delegation is allowed only when consumer CI is detected, and is always recorded

## Context

Five prompt files disagreed on whether LOW-risk slices need a verifier, and the config switch loop.validation.satisfiedByReview could waive validation in a repo with no CI at all. The skip now has one rule: one reviewer for LOW-risk slices, and the verifier is replaced by write-validation-result --decision skipped --skip-reason "delegated to CI: <workflow>" only when has-consumer-ci reports a push/pull_request-triggered workflow running the repo's test command; otherwise devcrew:verifier is dispatched. deriveValidationGate enforces the same condition at close.


## Decision

The decision in declarative voice. "We will …"

## Consequences

### Positive

- Validation is never silently waived: every skip is an artifact naming the CI workflow that covers it, and repos without CI always get a verifier.
- Consumer repos whose CI runs a test runner outside the known list (vitest/jest invoked directly, reordered args) are treated as no-CI and get a verifier dispatch they might not strictly need; extend KNOWN_TEST_COMMAND_PATTERNS when that shows up.
