# DEC-011: CLI auto-dispatch removed; slash flows are the contract

## Context

DEC-004 (SLICE-23) introduced the pending-dispatch marker file as a cross-process
spawn primitive. The design committed to a future SLICE-D that would ship a harness
consumer to drain those markers and actually invoke role agents. That consumer never
shipped. As a result, every CLI subcommand that called `dispatchAgent` wrote a marker
file and returned a placeholder string (`<marker-written:...>`); no agent ever ran.

v0.8.5 shipped a workaround for `/loop:backlog-enrich` proving the slash-flow pattern
(orchestrating via Claude tools inside the session) is viable and produces better
results than the deferred-consumer approach. FEAT-049 confirmed the marker consumer
is not planned — the slash flows are the permanent contract.

The four broken CLI surfaces were:

- `/loop:backlog enrich` — architect never classified; FEAT tags never written
- `/loop:backlog add` (researcher path) — body never enriched
- `/loop:spec decompose` (no --features path) — architect never derived FEATs
- `/loop:slice complete` async doc-writer — document-writer never ran

## Decision

We will remove `dispatchAgent` invocations from the four affected CLI subcommands and
document slash commands as the orchestration contract. Each affected subcommand either
refuses with a clear error pointing at the corresponding slash flow, or degrades
gracefully (backlog add still creates the FEAT with an empty body rather than refusing).

`dispatchAgent` and `appendAuditLog` remain exported from `auto-dispatch.mts` as
opt-in audit infrastructure for callers that want marker-write semantics. The marker
queue at `.claude/artifacts/loop/pending-dispatch/` is deprecated for production use —
no consumer is planned.

The `--no-research`, `--no-architect`, and `--no-doc-writer` flags are kept as no-ops
with a stderr deprecation note for backward compatibility. They can be removed in a
follow-up FEAT once telemetry confirms no usage.

## Consequences

### Positive

- CLI subcommands no longer silently no-op; intent is observable in the CLI exit code
  and stderr message naming the correct slash flow
- Marker files stop accumulating from the four removed call sites
- Contract is explicit and documented: slash flows are the orchestration primitive
- `dispatchAgent` remains available for callers that genuinely want async marker-write
  semantics (e.g. `feature-lifecycle.mts::classifySlice`)

### Negative

- CI or scripts that invoked the four CLI subcommands directly will now receive a
  non-zero exit with an explanatory message; callers must switch to the slash flow
- The `--no-research` / `--no-architect` / `--no-doc-writer` flags are now no-ops
  rather than meaningful opt-outs (a follow-up FEAT should remove them)

### Neutral

- `feature-lifecycle.mts::classifySlice` still calls `dispatchAgent` (out of scope
  per OQ-4 deferral); DEC-011 explicitly retains the function as opt-in infra

## Alternatives considered

- **Build the marker consumer (DEC-004 path)** — would have made the CLI surfaces
  work without changing their interface, but requires process management, retry
  logic, and a persistent harness daemon. The slash-flow pattern already works (v0.8.5
  proof) and is simpler to reason about. Rejected.
- **Remove `dispatchAgent` entirely** — cleaner but breaks `classifySlice` and any
  future caller that wants audit-trail semantics. Keeping the function as opt-in
  infra is the lower-risk path. Rejected.
