# DEC-002: getProvider falls back to NoopProvider for unknown provider names without warning

## Context

Unknown config keys at startup should not crash ceremony hooks mid-run. A silent no-op is safer than a throw. The alternative (warn + noop) was considered but adds noise for users who intentionally leave provider unconfigured.


## Decision

The decision in declarative voice. "We will …"

## Consequences

### Positive

- Positive: misconfigured repos don't break on loop start
- Negative: typos in `taskStore.provider` (e.g. "gitHub") produce silent no-ops, hard to debug without reading docs. A future improvement could add a startup validation pass that warns on unrecognized provider names.
