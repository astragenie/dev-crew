# DEC-057: _repoPath parameter kept for API documentation, all operations use child.worktreePath as cwd

## Context

The `repoPath` parameter originally appeared to serve as the working directory, but all actual git/gh operations use `child.worktreePath`. Renaming to `_repoPath` signals it is documentation-only and suppresses lint warnings without removing it from the public API surface.

## Decision

We will keep the parameter in the public function signature as `_repoPath` to document that callers may pass a repo root path, while all subprocess calls use `child.worktreePath` as `cwd`.

## Consequences

### Positive

- Callers who pass `repoPath` see it documented correctly
- Lint is clean with no `no-unused-vars` suppression comments

### Negative

- Slight confusion for readers who expect the parameter to be used directly

### Neutral

- No behavior change

## Alternatives considered

- **Remove the parameter** — would break callers that pass it; rejected to keep API stable
