# DEC-044: feature-toggle config is a top-level `features` block with default-ON resolution

## Context

The object passed to stop-conditions is the full parsed `loop.json`; loop keys read as `config.loop.*`, but `isEnabled` reads the flag at top level (`config.features`). Placing the block under `loop` (first attempt) made the lookup miss → default-ON → gate never disabled. Resolution: keep `features` top-level (sibling of `loop`/`stack`/`reviewers`), and make missing/malformed entries resolve to enabled so config drift can never silently disable a guardrail.

### Positive

- Disabling a gate is explicit and auditable; typos fail safe (stay enabled).
- Each new toggle must register in the `FeatureName` union AND the top-level block — a minor namespacing inconsistency with the `loop.*` keys; documented in `docs/halt-badges.md`.
