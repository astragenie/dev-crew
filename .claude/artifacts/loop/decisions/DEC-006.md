# DEC-006: Pair agent events by union of start+stop ids, not by stop ids alone

## Context

`subagent_stop` events lag behind their corresponding starts because the SubagentStop hook fires when the orchestrator returns control to the user — that can land minutes after `/loop:slice complete` runs. Counting agents only when their stop event was visible meant the writer collapsed to `agent_count: 0` for any slice whose builder dispatch was the last action before the close ceremony. Pairing on the union of agent_ids restores correctness without waiting for the stop, and the diagnostic note makes the partial-data case explicit to readers.

## Consequences

### Positive

- positive: agent_count is now load-bearing again; observability for builder-turn cost is restored across the marathon loop.
- positive: writer is robust to any future hook-lag, not just this specific symptom.
- negative: in-flight agents contribute zero turns and zero duration (no transcript path on start payload). Could be addressed by a follow-up pass that re-reads events.jsonl when the stop finally lands.
