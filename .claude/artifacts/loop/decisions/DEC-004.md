# DEC-004: Pending-dispatch marker file is the cross-process spawn primitive

## Context

No existing pattern in `loop` plugin for spawning a sub-agent from inside a Node CLI command (the existing `crew-bridge.mts` is invoked from within a dispatched agent, not the reverse). The simplest correct primitive is a marker file (`pending-dispatch.json`) that an outer harness consumes. SLICE-B/C/D will define the harness consumer + cleanup contract. Alternative considered: shell out to `claude` CLI with `--agent` flag — rejected because it couples the plugin to a specific CLI invocation shape and breaks under arbitrary host environments.

### Positive

- positive: dispatch is a pure file write — testable, idempotent, no process lifecycle to manage in SLICE-A
- positive: SLICE-D can implement async consumption + cleanup without rewriting SLICE-A
- negative: marker files accumulate until SLICE-D ships consumer + cleanup (reviewer flagged)
- negative: feedback loop from spawned agent back to caller is deferred (no streaming output to parent CLI)
