# DEC-064: A committed ingest.url without ingest.env never inherits the shell-global ASTRARUNNER_ENV tier for bearer resolution

## Context

FEAT-215 shipped the Path-2 direct sink `loop.ingest` block with
`ingest.env` optional (DECISION-1). The SLICE-140 review gate flagged a
MEDIUM footgun (Reviewer B): when a committed `ingest.url` supplies a URL
but omits `ingest.env`, `resolveEffectiveEnv` falls through to a
shell-global `ASTRARUNNER_ENV`. In a fleet where `ASTRARUNNER_ENV` is set
org-wide, the bearer's effective tier (e.g. `staging`) is paired with the
committed URL's tier (e.g. prod) — a wrong-tier send. Not
attacker-controllable, but a real misconfiguration hazard. The behavior
was documented and pinned by a test in `astrarunner-ingest.test.mts`
(the "Reviewer-B" pin) and deferred to FEAT-216 as a conscious
precedence change (`needs_contract: true`, `autonomous_safe: false`).

## Decision

The bearer token tier inherits the shell-global `ASTRARUNNER_ENV` /
plugin-option env **only when the URL is not committed** — i.e. only when
the URL itself was resolved from that same profile tier. When a committed
`ingest.url` is present and `ingest.env` is absent, the token tier's
effective env is `ingest.env` alone (`undefined` when absent), so the
bearer is resolved from the env-less default token store
(`resolveBearer(appId, undefined)`), never from the shell-global tier.

Concretely, token env resolution becomes:

1. `ingest.env`, when present, wins (unchanged — explicit tier).
2. else if a committed `ingest.url` is present → `undefined` (do NOT
   inherit `ASTRARUNNER_ENV`; a committed URL pins the URL's tier and the
   resolver cannot verify tier alignment without an explicit `ingest.env`).
3. else → `resolveAstrarunnerEnvOption()` (shell-global), because the URL
   in that case also came from the shell-global profile tier — the two
   are aligned.

The env-less default store is still permitted (tier-neutral: neither the
untagged committed URL nor the legacy `tokens.json` carries a tier claim,
so no mismatch exists). Only the shell-global *tier* is refused. In the
Reviewer-B scenario (only a tier-specific `tokens.<env>.json` exists, no
default store), this yields the fail-silent no-op
`{ posted: 0, skipped: N, failed: 0 }` — the wrong-tier bearer is never
sent.

Rejected alternative — hard-skip whenever `ASTRARUNNER_ENV` is merely set
(ignore even a valid default-store token): rejected as more surprising and
as coupling behavior to the presence of an unrelated env var. The
env-only rule above already guarantees no wrong-tier send.

## Consequences

### Positive

- Closes the SLICE-140 MEDIUM: a committed URL can no longer be paired
  with a shell-global-tier bearer.
- FEAT-215 AC-1 (committed `{appId,url}`, no shell env, default store)
  is unchanged — token env was `undefined` there already.
- The correct usage (pair `ingest.url` with `ingest.env`, or supply
  `LOOP_INGEST_TOKEN`) resolves a bearer as before.

### Negative

- Two FEAT-215 tests that exercised the hazard shape (AC-4 and the
  Reviewer-B pin) are updated/retired per FEAT-216 AC-2: AC-4 now declares
  an explicit `ingest.env` to keep proving URL-precedence with an aligned
  bearer tier; the Reviewer-B pin is replaced by a test asserting the
  fail-silent no-op.

### Neutral

- The URL resolution path (`resolveEffectiveEnv` for the profile URL
  fallback, only reached when `ingest.url` is absent) is unchanged — the
  URL and its bearer are tier-aligned there by construction.
