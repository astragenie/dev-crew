# DEC-005: appendAuditLog failure propagates to caller (does not swallow)

## Context

Matches the existing `crew-bridge.mts` audit pattern in this repo. Silent swallow of disk-full or permission errors would lose the audit signal that something is wrong with the loop's own bookkeeping — exactly the signal we want to surface, not hide. Caller may choose to wrap in try/catch if they have a fallback; library does not impose that policy.


## Decision

The decision in declarative voice. "We will …"

## Consequences

### Positive

- positive: disk-full / permission errors surface immediately rather than corrupting silent state
- positive: consistent with existing repo idiom — future maintainers don't have to learn two error patterns
- negative: if a caller forgets to wrap, an audit-log write failure could abort a CLI command. Mitigation: documented in module header and reviewer-flagged for SLICE-B/C/D wiring sites.
