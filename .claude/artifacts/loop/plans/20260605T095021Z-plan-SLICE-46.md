## Open questions

**Q1 -- Architect output format for classification (resolved)**

The architect agent standard output (agents/architect.md:20-55) is free-form Markdown -- not machine-parseable.
Resolution: send a tightly constrained prompt instructing the architect to return ONLY a compact key:value block:
  tags: [api-change, storage]
  needs_contract: true
  needs_ux: false
Parse with a new parseClassifyOutput(raw) helper. The parser scans for lines matching
tags: / needs_contract: / needs_ux: and ignores surrounding prose. Unparseable output = soft no-op.

**Q2 -- Placement in sliceFromFeature flow (resolved)**

Slice file is written at feature-lifecycle.mts:157. Tags must appear in the file before the function returns.
Decision: run classify AFTER fs.writeFile so the architect can reference the slice path,
then patch the file in-place with mergeFrontmatter.

**Q3 -- dispatchAgent is marker-based, not inline execution (resolved)**

dispatchAgent writes a marker file and returns immediately (auto-dispatch.mts:102-118).
The output field will be a marker path string, not actual architect text.
Resolution: follow the opts.dispatchFn injection seam exactly -- tests inject a mock
returning structured output; production harness provides a real dispatchFn.
If output is a marker path (not parseable as key:value), treat as soft no-op.

**Q4 -- Missing tags detection for backlog enrich (resolved)**

A FEAT is unclassified when ALL THREE hold: tags absent/null/[]; needs_contract absent/null; needs_ux absent/null.
If ANY field is explicitly set (including false), the feature is already classified -- AC-3 skip path.

**Q5 -- backlog enrich placement (resolved)**

Implemented as a new enrich sub under runBacklogSubcommand in loop.mts
(consistent with add, list, triage, promote, pm-write). Invoked as: loop backlog enrich.

**Q6 -- sliceFromFeature signature extension (resolved)**

Current: (repoPath, featureId, { config = null }).
Extended to { config, noClassify, dispatchFn }. Backward-compatible.

**Q7 -- Circular import risk (resolved)**

## Proposed approach

### Step 1 -- classify-parser.mts (new shared module)

Create src/scripts/lib/classify-parser.mts with one export:
  parseClassifyOutput(raw: string): { tags: string[]; needs_contract: boolean | null; needs_ux: boolean | null }

Parser logic:
- Scan each line of raw for key: value patterns.
- tags: parse inline array or comma-separated list.
- needs_contract / needs_ux: parse as boolean (true/false) or null if missing.
- Return defaults { tags: [], needs_contract: null, needs_ux: null } on empty/unparseable input.
- Export from loop.mts for testability: re-export parseClassifyOutput from classify-parser.mjs.

### Step 3 -- runSliceSubcommand opts seam in loop.mts

### Step 4 -- classify logic in feature-lifecycle.mts

Extend sliceFromFeature options bag: add noClassify?: boolean and dispatchFn?: DispatchFn.

After await fs.writeFile(slicePath, slice) at line 157:
1. AC-3 guard: if featureFM already has non-empty tags, skip classify (return result with classify: null).
2. Call the classify helper (new internal classifySlice function):
   - Build prompt: instruct architect to return ONLY the key:value block, referencing slicePath and featureId.
   - Call dispatchFn({ agent: "loop:architect", prompt, parentCommand: "slice from-feature",
     repoRoot: repoPath, argv: noClassify ? ["--no-classify"] : [], skipFlag: "--no-classify" }).
   - On result.ok && result.output: call parseClassifyOutput (imported from classify-parser.mjs),
     then mergeFrontmatter on slicePath to patch in tags, needs_contract, needs_ux.
   - On failure or unparseable: console.warn, return classify: null -- no throw.
3. Return value gains classify: { tags, needs_contract, needs_ux } | null field.

Classify prompt template:
  "Classify this slice for the orchestrate-slice router.
   Read <slicePath> for context. Respond with ONLY this key:value block -- no preamble, no headings:
   tags: [<labels from: api-change, storage, workflow, ux, auth, infra, test, docs, refactor>]
   needs_contract: <true|false>
   needs_ux: <true|false>"

### Step 5 -- runBacklogEnrich in loop.mts

New private async function runBacklogEnrich(repoPath, flags, opts):
1. listBacklog(repoPath) filtered to state === "triaged".
2. Partition: needsClassify (all three fields absent/null) vs alreadyTagged.
3. For each needsClassify entry: build classify prompt for the FEAT file, call dispatchFn,
   parse output, call updateFeatureFrontmatter(entry.filePath, { tags, needs_contract, needs_ux }).
   Soft-fail per entry (catch + warn, increment failCount).
4. Console output: print "Enriched: N / Already tagged: M" (AC-4 human-readable summary).
5. Return { enriched, alreadyTagged, failed }.

Add if (sub === "enrich") { return runBacklogEnrich(repoPath, flags, opts); } to runBacklogSubcommand.
