## Risks

- Pre-mortem 1 -- most likely cause of a failed review or validation two weeks out: a blanket find-and-replace. Three distinct traps. It must not rewrite agents/3rdparty/ (vendored and exempt per AGENTS.md), it must not rewrite prose and docs examples that describe development rather than shipped invocation (CLAUDE.md and docs/ deliberately stay on source paths), and -- the subtle one -- src/scripts/lib/install/shipped-entrypoints.mts sources CLI entries ONLY from literal invocations in commands/*.md and agents/*.md, so a rewrite that changes the literal shape in a way the extractor no longer recognizes would shrink the entry list and turn gate 42 green by discovering nothing instead of by passing. AC-2 exists specifically to make that failure mode impossible to merge.
- Pre-mortem 2 -- merged and broke the loop, what rollback requires: `git revert` of a markdown-plus-test-file commit is sufficient. No migration, no state cleanup, no cross-plugin coordination. The only contract-shaped change is gate 42 flipping from designed-red to blocking, and the same revert restores it. dist/ itself is untouched by this FEAT, so FEAT-026's bundles are not at risk.
- Pre-mortem 3 -- which existing test would NOT catch a regression here: nothing today asserts that a product-surface file may not name a source script path. That is precisely the `no-source-script-path` rule this FEAT adds. Until it exists, a later edit can reintroduce `bun crew/scripts/crew.mts ...` into a command and the only thing that would notice is a full consumer-smoke run (gate 42, ~180 s plus a 269 MB staging copy) -- too slow and too coarse to protect the invariant, which is why the validator rule is not optional polish.
- Entry-list honesty gap, documented by the suite itself at src/tests/install/consumer-smoke.test.mts:15-23: `crew/scripts/crew.mts show-workflow-state` is not invoked via bun anywhere in commands/*.md or agents/*.md today (commands/build.md reads workflow-state.json via jq instead; FEAT-029 would switch it), so it is absent from the entry list and cannot appear in EXPECTED_FAIL. Draining the set to empty therefore does NOT prove every real invocation runs -- it proves every DISCOVERED one does. Do not let the green gate be reported as stronger than it is, and expect FEAT-029 to add entries later.
- Blast radius is wide even though each edit is trivial: roughly 57 files across four product surfaces that ship to adopter repos. AGENTS.md Never-do warns against casually editing commands/, agents/, skills/ and templates/ -- here that editing IS the deliverable, but it means a careless slice can degrade the shipped product surface broadly in one commit. Per-surface slices (1, 2, 3) keep each diff reviewable.
- Merge-order hazard carried from SLICE-52's grade lesson: "The dist freshness gate is a merge gate as much as a commit gate: after merging two sibling lanes that changed bundled sources, build:dist --check went red for 10 bundles." This FEAT does not change bundled sources, so it should not trip that gate -- but it runs serially on a shared branch alongside other audit work, so `bun src/scripts/build-dist.mts --check` belongs in the AC-7 gate list to catch a sibling lane's drift rather than this FEAT's.
- Second-order: gate 42 becoming blocking makes a slow, 269 MB-staging suite a hard merge gate for everyone on the branch. If it proves flaky on the self-hosted runner, the pressure will be to re-add EXPECTED_FAIL entries rather than fix the cause -- the exact anti-pattern the ratchet comment at lines 9-13 forbids. docs/ci-gates.md should record the retry policy alongside the blocking flip.
