## AC-2 regression found and fixed (trailing-newline growth)

The first full bulk pass (16 adopters applied, all committed) surfaced a
real idempotence bug: `replaceMarkerBlocks` in
`src/scripts/lib/migrate-adopter-markers.mts` only `trimStart()`ed the
content trailing the marker block, so a trailing blank line/EOF newline
already present survived un-normalized inside the joined string while the
function's own final `` `${parts.join("\n\n")}\n` `` template literal added
one more line on top — growing the file's trailing blank-line count by one
every run. It was invisible in the local fixture-based unit/integration
tests because every fixture used in `src/tests/migrate-adopter.test.mts`
happened to end its content immediately at the marker block (nothing after
it), so the trailing-content code path was never exercised. It surfaced on
7 of the 16 applied adopters (`authentic`, `common`, `marketing`, `memory`,
`raskraska`, `runner`, `sales` — the ones whose CLAUDE.md has a
`## Project state (auto-generated)` section, or similar, after the marker
block) as a `changed` result on what should have been a pure idempotence
re-run.

Fixed by changing `after = content.slice(lastEnd).trimStart()` to
`.trim()` in `replaceMarkerBlocks` (devcrew commit `474be650`), with
regression coverage added to both the unit test
(`replaceMarkerBlocks: repeated calls with trailing content after the block
do not grow trailing blank lines`) and the integration idempotence test
(fixture now includes a `## Project state` tail). The 7 affected adopters
received a corrective commit and re-verified 0-diff idempotence.

## Reviewer-caught defect: unrecognized `loop:` legacy marker pair

Independent review (`.claude/artifacts/crew/reviews/20260819T154018Z-review-result-slice-26-migrate-adopter.md`,
`needs_fix`) round-tripped the real migrated adopters and found that
`replaceMarkerBlocks` only recognized `crew:`/`runner:`/`devcrew:` marker
literals — not a **third** legacy pair, `<!-- loop:start -->...<!-- loop:end -->`,
used by an older "Wiggin Loop" installer (`/loop:install`) that predates the
runner-plugin rename. Effect: the script left that span completely
unrecognized (untouched as ordinary prose), so `rewriteDispatchTokens`
(which runs over the whole file, not scoped to marker spans) rewrote
recognizable dispatch tokens *inside* it too — leaving a duplicate, stale
"## Autonomous Loop — HARD RULES" section with a broken mix of old and
half-rewritten tokens (e.g. `/loop:phase-gate` next to `/devcrew:build`)
sitting right next to the correctly-rendered devcrew block.

**Correction to the review's repo list**: the review named 7 adopters
(the same 7 as the AC-2 list, assuming full overlap). A direct grep for
`<!-- loop:start -->` against the live files disproved that: **`sales` has
zero loop: markers** — `git log --oneline -- CLAUDE.md` shows an earlier,
unrelated commit (`89de31a docs: agentic-setup rebuild — altitude model`)
that had already rebuilt/slimmed its CLAUDE.md before this migration ever
touched it, so it never carried a loop: block to begin with. The actual
loop:-affected set is **6 of 16**: `authentic`, `common`, `marketing`,
`memory`, `raskraska`, `runner`.

### Fix

`src/scripts/lib/migrate-adopter-markers.mts`: added
`{ start: "<!-- loop:start -->", end: "<!-- loop:end -->" }` to
`LEGACY_MARKER_PAIRS`, folded into the same first-start-to-last-end collapse
as `crew:`/`runner:` — a `loop:` span is now removed by `replaceMarkerBlocks`
*before* `rewriteDispatchTokens` ever runs over the content, so nothing
inside it (rewritten or not) can survive.
`src/scripts/migrate-adopter.mts`: `hasLegacyMarkerBlock` (used by
`enumerateAdopters`) now also matches `<!-- loop:start -->`, so a repo
carrying only a loop: block (no crew:/runner:) is enumerable.

### Regression tests added (4, all confirmed to fail on the pre-fix code)

Verified by temporarily reverting both source files (`git stash push --

- `enumerateAdopters: finds a repo carrying only a loop: block (no crew:/runner:)`

Test count: `src/tests/migrate-adopter.test.mts` now has **25 tests**
(21 pre-review + 4 new). Prior ledger draft claimed 24 — inaccurate, per the
review's own correct count; this revision fixes it.

### New adopters discovered — `citylive`, `devops` (migrated, scope decision by lead)

Re-enumerating with the loop: fix live (`enumerateAdopters` against the same
two roots) surfaced **2 adopters outside the original 18**:
`C:\work\mega\citylive` and `C:\work\mega\devops` — both carry a
`loop:`-only block (no crew:/runner:), invisible to the original
crew:/runner:-only enumeration.

Both also carry a **fourth, unrelated marker namespace**,
`<!-- engineering-os:start -->...<!-- engineering-os:end -->`, whose body
reads "Engineering OS global memory lives in ~/.claude/engineering-os/. Run
`/crew:install` after plugin updates that change framework memory." This is
not a `crew:`/`runner:`/`loop:` pair (`migrate-adopter-markers.mts` correctly
leaves the marker itself alone), but `rewriteDispatchTokens` is not
marker-block-scoped — it runs over the whole file — so migrating either repo
would also rewrite that block's `/crew:install` mention to `/devcrew:install`.

Flagged to the lead before acting; **decision: migrate both, keep the
whole-file token rewrite as-is.** Rationale: post-cutover the crew and
runner marketplace entries are retired, so every `/crew:*`/`/runner:*` token
anywhere in an adopter — including inside the engineering-os block — is a
dead command; rewriting it to `/devcrew:*` keeps the doc accurate rather
than damaging it. The `engineering-os:` marker pair itself stays
unrecognized and untouched (a distinct, deliberately-preserved namespace,
not this migration's to collapse) — only the token inside its prose was
rewritten, because the underlying command it names no longer exists.

Both migrated with the standard dry-run → apply → idempotence-re-run →
commit sequence: `citylive` (commit `a077750d`) and `devops` (commit
`334e6c32`), both 0-diff on the idempotence re-run, both end with exactly
one `devcrew:start/end` block, zero `runner:`/`crew:`/`loop:` leftovers, and
the `engineering-os:start/end` marker pair intact (its `/crew:install`
mention now reads `/devcrew:install`).

### Real defect found and fixed first (blocking, not a scope choice)

First attempt (installer run, `migrate-adopter --dry-run` against `kb`)
surfaced a genuine data-loss bug in `replaceMarkerBlocks`
(`src/scripts/lib/migrate-adopter-markers.mts`): it collapsed everything
from the FIRST marker span's start to the LAST marker span's end into one
block, discarding any hand-authored content sitting *between* two separate
spans. Invisible across all 18 SLICE-26 adopters (their `crew:`/`runner:`
blocks always sat adjacent). Fatal for `kb`/`standards`: neither had ever
had a `runner:` block, so `/devcrew:install` appends the new one at
file-END, while the pre-existing `crew:start` sits at the top — sandwiching
the entire hand-authored document body (kb: ~130 lines Mission/Core Mental
Model/Navigation/Update-triggers; standards: ~62 lines
Mission/Repository-Structure/Standards-Philosophy/Safety-Rules) in between.
`--apply` would have deleted all of it. Work stopped short of `--apply` on
first pass, both repos reverted to pristine (`git status --porcelain`
empty), finding reported to the lead rather than forced around.

Lead adjusted SLICE-31 scope to include the fix (normally
`migrate-adopter`/installer are consumed as-is). Fixed by cutting each span
out independently and preserving all other content (including inter-span
gaps), inserting the single rendered block at the first removed span's
position; the AC-2 trailing-trim behavior (SLICE-26) is unchanged. 2
regression tests added (far-apart spans; three interleaved spans),
confirmed to FAIL on pre-fix code via `git stash` round-trip
(`AssertionError: expected surviving body to include: ## Mission` and
`AssertionError: false == true` on the inter-span content check) before
being restored to pass. Re-verified zero-diff `--dry-run` against 3
already-migrated real adopters (`authentic`, `dating`, `memory`) to confirm
the SLICE-26 estate is unaffected. Full gate run after the fix: `tsc`
(both configs) clean, `biome lint`/`format` clean, `migrate-adopter.test.mts`
27/27 pass (25 prior + 2 new), full suite `bun test src/tests/ --parallel`
3358 pass / 7 skip / 0 fail across 329 files. Committed to devcrew `main`
as `b1799c11` ("fix(SLICE-31): preserve inter-span content in
migrate-adopter marker collapse").
