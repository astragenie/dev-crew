## Lessons

- Three-slice arc on PM-dispatches-spec-writer (SLICE-111 grant Agent, SLICE-112 add ToolSearch instruction, SLICE-113 grant ToolSearch). Each iteration surfaced a layer of the deferred-tool model. Now the lessons digest needs ONE rule: granting a deferred tool requires granting BOTH the deferred tool AND ToolSearch in the same frontmatter edit, AND adding a ToolSearch invocation instruction in the body. Three things together.
- Validation-driven discovery worked AGAIN. Three iterations, three real bugs. Cheaper than designing the full wiring up front.

## Surprises

- v0.43.3's body-only instruction was insufficient because PM couldn't invoke ToolSearch without granting it. Looks obvious in retrospect.

## Followups

- Update `loop:learn` entry for `deferred-tool-toolsearch-gap` with the corrected rule (need BOTH ToolSearch grant AND Agent grant + body instruction).
- Audit other loop agents that grant Agent: do they grant ToolSearch too? Likely no.
- Re-run FEAT-085 retriage after v0.43.4 install. End-to-end validation.

## What went well

- One-line frontmatter edit. One new test. ~5 min slice.
- Pattern is now triple-locked: tools grant + ToolSearch grant + body instruction.

## What went wrong

- Should have caught this in SLICE-111 (FEAT-195 original Agent grant). The deferred-tool model isn't documented in plugin-dev:agent-development skill — file a request against that skill maintainer.

## What I would do differently next time

- When granting any deferred tool, default to granting ToolSearch too. Frontmatter checklist for deferred tools should be: grant the tool + grant ToolSearch + add a body instruction telling the agent to ToolSearch the tool's schema before use.
