## Lessons

- Two-phase slash command without a CLI surface is the right level for orchestrating EXISTING agent dispatches. No new contract surface to verify at runtime; the test pins the contract document itself.
- Intent-based test assertions (regex on phase labels + halt language) keep the test durable across future copy-edits to the markdown. Pinning exact prose would false-fail on every readability tweak.
- Final summary invariant `N = D + C + F` documents the addition so operators can quickly verify a phase did not silently drop FEATs.

## Surprises

- The `addFeature` CLI path stamps a stub body and overrides any pre-written content. Had to fill the FEAT body AFTER promotion. Worth flagging: `backlog add --body <file>` would let callers seed real content in one shot.

## Followups

- Consider deprecating one or both legacy commands in a future release once `/loop:intake` is the proven default. Not now; back-compat helps adoption.
- Wire `/loop:intake` invocation into `/loop:start` flow when new FEATs are detected in pending/.

## What went well

- 5 tests, 5 distinct contract surfaces (frontmatter, phase ordering, decline filter, back-compat, summary). No coupling.
- CLAUDE.md update is one paragraph, surgical, doesn't conflict with prior structure.

## What went wrong

- First attempt to overwrite FEAT-189 file failed because `addFeature` had already written the stub and the file was at a different path than my mv expected. Wasted ~2 min recovering. Documented as a "what went wrong" surprise above.

## What I would do differently next time

- After `backlog add`, immediately read the file at the returned path and overwrite via Edit/Write, BEFORE doing any state transitions.
