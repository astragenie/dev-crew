## Lessons

- Machine-wide caps need a single fleet-wide ledger file, not per-repo state — a correlated CI failure across N repos must trip one shared limit; compound keys (ghSlug::findingId) keep cross-repo entries disambiguated.
- Every in-flight/claim style ledger entry needs a staleness TTL prune at read time (mirroring COND-1) so a crashed reaction can never permanently occupy a concurrency slot.
- Gate-check reads must be read-only and never create the ledger file — assert this with an explicit never-creates-the-file test, not just a returns-zero test.
- Sequential for+await sweeping plus the single-tick lockfile is what makes a lock-free gate read safe (stale-but-never-torn); if sweeping ever goes Promise.all, the gate needs a lock.
