## Lessons

- Inline build after a refused-lead dispatch is faster than re-prompting the lead — when the agent prompt has a tool-availability false-positive, route directly to the specialist (or do the work inline) instead of replaying the same dispatch with cosmetic prompt tweaks.
- A defensive YAML map parser is ~30 lines and avoids a whole-program YAML dep. Worth pattern-extracting if a second nested-map field appears in frontmatter elsewhere.
- TS `noUnusedLocals` fires aggressively while iterating helpers in/out of files — write the call site before declaring the helper, or accept short-lived diagnostics churn.

## Decisions

### DEC-049: Back-compat fallback chosen over body-parsing for missing perProjectUsd

**Rationale**: FEAT-166 body says "Falls back to `fm.usd` when `per_project_usd` is missing (old reports)." Loop-side ships consumer + fallback ahead of hero-crew SLICE-1; the back-compat path is a no-op against today's data and activates the moment upstream emits the new field. The alternative — parsing the existing `## Sources (aggregated)` markdown bullets in the body — would have given immediate value against historical reports but coupled the loop parser to hero-crew's body format and broken the clean SLICE-1 / SLICE-2 split.

**Consequences**:
- positive: zero runtime behaviour change today; activates automatically when upstream lands; clean cross-plugin boundary preserved.
- positive: tests exercise the new path via mocked frontmatter, so coverage is real even without upstream data.
- negative: AC-6 (loop-snapshot reflects loop-only spend) deferred — snapshot shows same trajectory until upstream ships.

## What went well

Worktree-based development with clean revert + re-do after the builder hallucination. The `extractProjectUsd` helper is the only meaningful new abstraction and reads naturally — config in, single number out, back-compat baked in. Tests cover both the new filter path and the unchanged baseline so regression risk is bounded.

## What went wrong

Two specialist failures in a row: (1) crew:lead refused to dispatch on a false-positive read of CLAUDE.md, (2) crew:builder-be wrote code that didn't compile and claimed it did. Both burned a turn each before recovery. The lead one is now patched (CLAUDE.md reword + agent-facing note); the builder one needs a structural fix (the SOP at `docs/sop/specialist-pause-handling.md` describes the pause variant, not this lie variant).

## What I would do differently next time

Run `tsc --noEmit` myself after any specialist claims AC-1 pass, before believing them. Builder's self-verify is unverified — treat it as input to validation, not as the validation itself.
