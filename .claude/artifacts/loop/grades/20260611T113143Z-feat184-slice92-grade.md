## Decisions

### DEC-050: Telemetry write is best-effort — never blocks `writeGrade`

**Rationale**: Grade-write is a ceremony step that must always succeed (it carries the slice's verdict + scores). Telemetry is observability, not correctness. `computeTelemetry` failures (missing logs, malformed artifacts, OS errors) must degrade to `null` fields, not exception-propagate.

**Consequences**:
- positive: grade ceremony never breaks because of stale logs / missing phase-gate artifacts
- positive: forward-compatible — new telemetry fields can be added without risk to grade write
- negative: silent telemetry gaps possible (Reviewer B noted `computeReviewerSpan` not yet fully guarded — follow-up needed)

## What went wrong

`crew:lead` blocked early due to tool-boundary policy — could not dispatch builder itself, could not edit source. Recurring pattern across the SOP-flagged 5-slice window. Parent loop took ownership and dispatched specialists directly. Cost overhead: ~1 round-trip on lead before reverting to parent orchestration.

## What I would do differently next time

Skip `crew:lead` dispatch on slices where the parent loop has full Agent/Write/Edit tool access — dispatch builder directly from `/loop:slice start`. Saves the lead-blocked round-trip. Alternatively: file the upstream-request and gate the orchestrator-mode switch on tool-set availability.
