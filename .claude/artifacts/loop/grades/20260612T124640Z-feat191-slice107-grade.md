## Lessons

- Stale-config silent fallback was the right migration strategy. Operators with `orchestratorMode: "lead"` in their `.claude/loop.json` get `slice-build` behavior without seeing a hard error. The new test pins this contract so a future "strict mode" refactor can't drop it accidentally.
- Cross-module refactor cost stays low when the type system enforces the union. Adding `as OrchestratorMode` at one default-param site was the only escape hatch needed — every other consumer caught the breakage at tsc time.
- Orphan-test removal dropped 4 tests (lead-emit + direct-builder-emit + direct-builder back-compat + a lead-default check). 1 new test pins the FEAT-191 fallback contract. Net surface-area decrease.

## Surprises

- `crew-bridge.mts` had `owner: "lead"` baked into a handoff-artifact frontmatter at write-time. Changed to `owner: "parent-loop"` — semantically more accurate now anyway.

## Followups

- Drop tests targeting previous-plugin-version crew (e.g. `_crewVersionOverride: "0.9.0"` / `"0.10.x"` in slice-start.test.mts). Greenfield + system-stability mode; legacy version coverage is dead weight. Track as FEAT-192.
- Walker auto-flip default to `slice-build` is no longer optional — it's the only sane default now. Already done as part of this slice's `resolveOrchestratorModeConfig` change.

## What went well

- TSC caught every consumer of the removed union members. Zero runtime surprises.
- Test gates dropped 4 orphans + added 1 fallback test — coverage of `slice-build` paths preserved.
- CLAUDE.md + CHANGELOG explicitly call out the breaking change and migration story.

## What went wrong

- Initial slice-start test had a leftover `sliceContent: "---\ntags: [fe]\n---"` that contradicted the test name "no tags". Caught by the first test run. Fix was one prop deletion.

## What I would do differently next time

- Read both the test name AND the test body before flipping assertions. Skim led to a contradicting fixture on the first pass.
