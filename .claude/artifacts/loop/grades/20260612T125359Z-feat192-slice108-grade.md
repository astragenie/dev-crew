## Lessons

- Dead options on public function signatures rot fast. _crewVersionOverride was no-op for one day before this cleanup; six callers carried the dead arg. Future: when removing a code path, search-and-remove the no-op option in the SAME slice instead of leaving a TODO.
- Greenfield discipline: if there's no operator + no live test depending on a code path, the code path is dead. Don't preserve "for compat" when there's no compat consumer.

## Surprises

- 1292 pass / 0 fail on first run after the cleanup. No regressions. Validates that _crewVersionOverride truly was a no-op.

## Followups

- Continue noise reduction: legacy crew-version branches in plugin-identity / crew-bridge could be candidates if they're not exercising live code paths. Audit when convenient.

## What went well

- Pure mechanical removal. tsc caught the only consumer (the signature itself). No fragile test fixtures to rewrite.
- Test count unchanged at 1292 but the dead args + no-longer-meaningful test name fixed.

## What went wrong

- Nothing significant.

## What I would do differently next time

- Couple the no-op-option removal with the underlying behavior removal. Don't ship the option-as-deprecated-stub pattern.
