## Lessons

- Replacing a contract in four near-identical prompts needs a test that reads all four; the guardrail-phrase test only read fullstack-dev.md, so two builders kept the old "commit -> PR report" paragraph until a reviewer read them by hand. builder-report-contract.test.mts now asserts the legacy phrases are absent in every builder.
- Decision ids are allocated per branch at close time, not reserved by the spec: a spec that says "DEC-040" is a placeholder. Lanes that mint a DEC file directly must renumber at merge; let grade-write allocate instead, or check the branch's highest id right before committing.
- A validator rule keyed on frontmatter `tools:` is inert for every agent that omits the field. Treat absence as all-tools unless `disallowedTools` names the capability, and keep a fixture that fails for the absent-field case.

## Decisions

### DEC-047: Builder report contract is a marker-first final message; no publishing before review

**Rationale**: Builders mandated push + draft PR + report-to-pr before reporting, bypassing the dispatcher's explicit-approval ship boundary, and contradicted each other on the reporting channel. The two live hooks key on a line-start DONE/BLOCKED/HELP/IN-PROGRESS marker, so the block must start with the marker. Supersedes DEC-038's SendMessage receipt lane.

**Consequences**:
- Builders return a 4-line block (marker, FILES, TESTS, NEXT) as their final message; no PR comment, no handoff requirement, no SendMessage; validate-agents enforces no-prereview-publish and no-relative-script-path.
- report-gate.mjs's SendMessage scan is documented as retired/optional; any consumer that relied on the PR-comment receipt must read the SubagentStop final message instead.

## Surprises

- The lane minted DEC-046 while SLICE-53's close allocated DEC-046 on the branch minutes earlier; caught by a dry-run merge-tree before dispatching reviewers.
- All four builders carried the "PR report" substring even where the contract section was correct, so the new regression test required a wording tweak ("pull-request comment") to avoid a false positive on legitimate text.

## What went well

Resume from the interrupted worktree needed only the validator-rule diff to be finished. Reviewer B's manual read caught a contradiction no test covered, the fix landed in one commit with a test that provably fails on the pre-fix tree, and the verifier drove the real hook functions and validator against fixtures rather than trusting the unit tests.

## What went wrong

The decision-id collision cost a renumber round, and the first renumber commit silently dropped its content edits because a `git add -A --` pathspec failed, so it took two commits.

## What I would do differently next time

Check the branch's highest DEC id (or let grade-write allocate) before a lane writes a decision file, and make the contract test read every builder from the start.
