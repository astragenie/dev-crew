## Lessons

- Filesystem-lock polling budgets (80 attempts / ~2s) that pass in isolation blow up under full-suite load — same-process callers must serialize via an in-process promise-chain mutex; reserve the mkdir lock for genuine cross-process contention only.
- Promise-chain mutex cleanup must compare the map entry against the caller's own promise object before deleting (get(key) === run) — otherwise a finished early link deletes a later caller's live chain entry.
- prior.catch(() => {}) inside the chain link prevents one rejected update from poisoning subsequent same-key callers while each caller still observes its own rejection.
- TTL steal tests that assert claimedAt is OVERWRITTEN (not merely present) are the only shape that catches a steal that forgets to re-stamp the claim.

## Surprises

- The watch-state failure was load-dependent lock-arbitration, not a lost-update bug — deterministic repro required a standalone stress script with simulated CPU load (N=60 writers).
