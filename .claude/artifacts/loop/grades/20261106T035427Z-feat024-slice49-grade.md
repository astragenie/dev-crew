## Lessons

- A gate that compares two vocabularies (ladder slot labels vs reviewer role keys) will pass its own unit tests and never fire in production; the only honest regression test uses the exact strings the shipped agent prompts emit (typescript-reviewer, reviewer), not synthetic A/B.
- Root `bun run typecheck` covers two tsconfigs, not crew/tsconfig.json; a lane that only runs the root script can leave CI gate 36 red. Lane gate lists must name all three projects.
- Fixing the aggregation without fixing the dispatch prompt would have reintroduced last-writer-wins under a different key — the stock reviewer wrote no --reviewer at all. Check who produces the key, not just who consumes it.

## Decisions

### DEC-043: Review/validation gates require explicit terminal verdicts; ladder entries are slots counted by distinct approving keys

**Rationale**: Scaffold/in-progress writes used to stamp review_passed with no verdict, and one reviewResult slot made reject-then-approve green (Codex #20/#21). `--decision` is now required on terminal writes; scaffolds register no verdict. `required` snapshots reviewers.ladder at run-brief time but is interpreted as a slot count because ladder labels (A/B) never match the role-name keys reviewers actually write; the fanout prompt now hands each reviewer its slot key so two stock reviewers cannot collapse onto one key.

**Consequences**:
- Any rejection fails the gate regardless of order; passed requires as many distinct approving keys as ladder slots; validation skipped requires --skip-reason. Adopter prompts that omit --reviewer still work but both reviewers must write distinct keys to reach passed.
