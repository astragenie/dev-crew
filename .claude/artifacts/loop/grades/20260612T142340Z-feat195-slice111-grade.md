## Lessons

- Live validation via the sample retriage run on 3 FEATs was the right way to find the wiring gap. The unit tests for /loop:retriage all passed because they only checked markdown contract; the runtime check exposed the real bug.
- Agent tool grant on a "read-only" agent needs prose discipline to prevent scope creep. Documenting the in-turn dispatch restriction inside the agent body is the cheapest enforcement — review catches violations.

## Surprises

- Security score lowered (0.85) because granting Agent to PM widens the blast radius of a prompt-injection attack against PM. Mitigation is purely prompt-discipline. A future hardening FEAT could add a runtime check that PM only invokes Agent with subagent_type === "loop:spec-writer".

## Followups

- Re-run the sample retriage (FEAT-085 / FEAT-100) to verify PM now successfully dispatches spec-writer end-to-end.
- Consider a guard hook that audits PM's Agent calls and blocks anything other than loop:spec-writer.

## What went well

- 4 tests pin the contract surface (frontmatter tools, description string, body rule, retriage cite). Durable across copy-edits.
- Sample retriage run from earlier in the session diagnosed the bug + dictated the fix; this slice was just plumbing.

## What went wrong

## What I would do differently next time

- When designing a multi-agent contract (PM dispatches spec-writer), validate the tool ACL up-front by attempting the dispatch in a fixture before shipping the contract. Would have caught FEAT-195 during FEAT-193 design.
