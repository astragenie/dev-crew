## Decisions

### DEC-037: HTML-comment clause-id convention

**Rationale**: HTML comments don't render in Markdown viewers, so prose stays clean. Easy to grep (`grep -n "<!-- clause:"`), easy to extract (regex). Stable: H2 text can be lightly edited without breaking the id. Kebab-case derived from H2 title for human readability.

**Consequences**:
- positive: zero visual change to CLAUDE.md when rendered
- positive: trivial machine extraction via 1-line regex
- negative: rename of an existing clause silently breaks all outstanding `declined_per` citations; no rename-aware tooling yet
- negative: requires care to keep id and H2 wording aligned over time

### DEC-038: Hardcoded clause list in agents/pm.md

**Rationale**: PM prompt currently embeds the valid clause list verbatim so PM sees them inline without needing to read CLAUDE.md. Trade-off: ergonomic for the agent, but drift risk when CLAUDE.md adds/removes H2.

**Consequences**:
- positive: PM prompt is self-contained — no extra Skill/Read step before scoring
- negative: list will go stale on every CLAUDE.md H2 add/remove; future cleanup may shift to live-injection via `resolve-skills`-style preamble
- followup: monitor for first drift event; if it bites, replace hardcoded list with a `read clauses` step in PM dispatch wiring

### DEC-039: Missing-citation triggers triage fallback (not hard error)

**Rationale**: Triage skill treats malformed PM output (including missing `declined_per` on P4) as a fallback trigger, not a halt. CI gate catches it on next push. Within-loop feedback is deferred but operator gets it eventually.

**Consequences**:
- positive: keeps loop running through PM-output anomalies
- positive: regex-fallback default of 0.5 yields a safe P3 score, not silent acceptance of a bad P4
- negative: within-session, the missing citation is invisible until the operator runs CI or the validator manually

## What went well

Builder pause was caught post-fact and main thread wrote handoff from gate evidence without re-dispatch. ## What went wrong

Builder paused before writing handoff (same boundary as SLICE-82 test-coverage). Reviewer's first dispatch burned 53 tools on plugin-validator + skill-reviewer side-quests outside slice scope; tight retry needed. Both indicate that "self-verify" and "side-quest exploration" are the two biggest sources of agent context overrun.

## What I would do differently next time

1. Bake the ≤15 tool + inline-output budget into reviewer and validator agent prompts globally — don't rely on per-dispatch repetition.
2. Pre-write a handoff stub before dispatching builder, so post-pause recovery is a single Edit rather than a fresh Write.
3. For doc-only patches (e.g. adding HTML comments), consider skipping reviewer + validator entirely with a `requires_validation: false` waiver — current slice's "additive comment + new validator" is borderline, but the validator code itself does deserve real review.
