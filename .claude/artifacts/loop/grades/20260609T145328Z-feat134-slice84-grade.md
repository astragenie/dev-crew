## Lessons

- Library-only slices should set `requires_validation: false` in frontmatter upfront — skipping the validation gate at slice close is auditable but adds friction; the right place to decide is at slice authoring time.
- Running `npm run format:check` after build (not just `npm run build`) catches prettier divergence before the review ladder; builder's `format:check` step should be mandatory, not optional.
- LSP false positives on cross-module imports ("declared but never read") are a recurring noise source in this repo — `npm run typecheck` is the authoritative pass signal, not the IDE.

## Decisions

### DEC-040: ENOENT returns empty string instead of throwing

**Rationale**: Repos without a `skills/` directory are the common case for new installs. Throwing would block `installLoop()` for all pre-existing repos on upgrade, which is unacceptable. Returning `""` means the `{{skillActivationBlock}}` token renders as empty — safe no-op.

**Consequences**:
- Graceful degradation for all repos without skills — no upgrade friction.
- Silent skip if `skills/` is misconfigured (wrong path, wrong permissions). Would need an explicit `--debug` flag to surface, which doesn't exist yet.

### DEC-041: Only `manual` and `glob` triggers emit activation lines; `always_on` and `model_decision` are silently filtered

**Rationale**: `always_on` skills require no agent instruction — they're unconditionally loaded. `model_decision` is at the model's discretion by definition. Adding them to the activation block would be redundant noise. Only conditional triggers need explicit guidance.

**Consequences**:
- Clean, minimal activation block — only actionable instructions appear.
- A skill mis-tagged as `always_on` when it should be `manual` will be silently omitted from the block with no warning.

## Surprises

- `npm run format:check` diverged from built output after builder ran — prettier and tsc disagree on trailing newlines/semicolons in output files. Expected the builder to handle formatting before handing back.
- `buildSkillActivationBlock` and `parseSkillFrontmatter` both triggered "declared but never read" LSP warnings despite being correctly imported and called in `loop-installer.mts`. Root cause: LSP cache was stale; `typecheck` confirmed no real issue.

## Followups

- Consider adding `--debug` / verbose mode to `buildSkillActivationBlock` that logs skipped entries (ENOENT, unreadable SKILL.md, non-matching triggers) for troubleshooting.
- Subsequent FEAT-134 slices: wire `{{skillActivationBlock}}` into the actual rendered MASTER_PROMPT.md at install time and add an integration test that calls `installLoop()` with a fixture `skills/` directory, asserting the prompt contains the expected block.
- Add `requires_validation: false` as the default for library-only slices in `SLICE_TEMPLATE.md` to avoid the skip-validation-check workaround.

## What went well

`parseSkillFrontmatter` and `buildSkillActivationBlock` are clean, self-contained helpers with no side effects. The separation into a dedicated `skill-frontmatter.mts` module kept `loop-installer-tokens.mts` from bloating. Test coverage was comprehensive — all ENOENT paths, empty dirs, mixed trigger types, and the extras passthrough in `buildTokens` — covering real failure modes rather than just happy paths. Both reviewers reached the same verdict independently with no revision required.

## What went wrong

Format check failed post-build — the builder committed code that passed `tsc` but not `prettier`. Had to add a manual `npx prettier --write` + rebuild pass before the review. This cost one extra round-trip and left a gap in the builder's output quality bar.

## What I would do differently next time

Set `requires_validation: false` in slice frontmatter at authoring time for library-only slices. Add `npm run format:check` as an explicit builder exit gate (not just lint + typecheck). For cross-module imports, run `npm run typecheck` immediately after wiring to catch real errors before assuming LSP noise.
