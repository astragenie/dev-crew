## Lessons

- Crew agent frontmatter is the right place to grep for dispatch limits — `maxTurns: 40` was the smoking gun and took 30 seconds to find once I knew where to look.
- FEAT-031 SLICE-28's parser hardening helps research like this: turn counts now visible in agent reports even when stop events are delayed, which is what made SLICE-23's 66 turns readable as evidence.
- Counter-pattern in v0.7.2 CHANGELOG ("first slice that did NOT exhibit the pattern") was an independent observation that converged on the same conclusion. Two observers, same root cause.

## Surprises

- Hypothesis 2 (context window pressure) was rejected easily because SLICE-22 — a non-truncated run — was the highest-token slice in the window. Disconfirmation was cleaner than confirmation.
- Hypothesis 3 (tool budget) is not testable from inside this plugin. Documented as such rather than guessing.

## Followups

- Codify Option B (parent recovery rule) in `.claude/loop/rules.md` — when builder stops mid-cleanup, parent inspects gates + finishes inline rather than re-dispatching.
- Track clean-close rate over next 5 slices to validate Option A discipline (target: truncation drops from ~57% to ≤20%).
- If clean-close rate stays low, file follow-up FEAT against crew to bump `maxTurns` from 40 → 60 with this research as evidence (Option C).

## What went well

Research spike took 5 minutes once the agent-report numbers were in hand. Single grep + single file read identified root cause. Findings doc is concrete (specific file/line evidence) and ranks mitigations by cost.

## What went wrong

Initial framing assumed "parent has to manually finish" was a generic recovery — turns out 3 of 4 truncations were silent (state on disk was correct, parent just didn't know to verify). Recovery rule should explicitly inspect file system after silent stop, not only when work is obviously incomplete.

## What I would do differently next time

Look at the dispatcher's config first for any "investigate weird agent behavior" research. Most behavior caps are explicit and grep-able.
