## Lessons

- A bundle is only self-contained if every reachable module resolves data from the plugin root, not from import.meta.url. Four resolvers (presets, templates, decisions, grades) plus github-sync and otel-bridge still assumed the src/ or scripts/ layout; the FEAT's "65-module audit" claim was not real until reviewer A ran the bundled CLI from a clean directory and hit ENOENT. Run the shipped artifact from outside the repo before claiming the audit is done.
- The dist freshness gate is a merge gate as much as a commit gate: after merging two sibling lanes that changed bundled sources, `build:dist --check` went red for 10 bundles. Rebuild and recommit dist/ as the last step of every merge onto a shared branch.
- A regex that recognises the pre-migration path shape will silently match nothing after the migration it enables; collectHookEntries only matched `.mts` hook paths and the next build rm-rf'd 24 committed bundles. Recover entries by basename across the known source dirs and fail loudly on 0 or 2+ matches.
- Bun drops comments and unused top-level consts even with minify:false, so comment-only edits never trip the staleness check. Document it so nobody reads a green check as "source unchanged".

## Decisions

### DEC-048: Shipped hook and CLI entry points are self-contained dist/ bundles, not auto-installed dependencies

**Rationale**: Claude Code auto-installs plugin-root dependencies for marketplace installs, but devcrew is ineligible (root bun.lock declares workspaces, crew/ depends on a git URL, @astragenie/* needs registry auth at install time) and crew/'s own package.json is never installed. Bundling via Bun.build (target bun, external @opentelemetry/* and @aws-sdk/*) needs no network, no auth, and no install step; dist/ is committed and gate 21 (`build-dist.mts --check`, Bun version pinned by .bun-version) keeps it fresh.

**Consequences**:
- hooks/hooks.json bun commands point at dist/hooks/*.js; crew.mts/loop.mts/report-to-pr/prune-artifacts/watch-tick ship as dist/*.js; every bundled module resolves data files from CLAUDE_PLUGIN_ROOT with the legacy layouts as fallback.
- commands/*.md and agents/*.md still reference source paths until W2.5 rewrites them; the consumer-smoke ratchet stays red (42 CLI entries) until then. Each merge touching bundled sources must rebuild and commit dist/.

## Surprises

- The lane's first build silently deleted 24 committed bundles because collectHookEntries matched zero entries post-migration; the builder found it only by inspecting the 54k-line uncommitted deletion left by the interrupted session.
- Four of seven fixed resolvers carry a byte-identical CLAUDE_PLUGIN_ROOT-or-fallback block; reviewer A accepted it with a note to extract one helper.
- With CLAUDE_PLUGIN_ROOT unset, dist/loop.js preset resolution still ENOENTs three dirs above dist/ (fallback is for src/ and scripts/ layouts, not dist/); acceptable because Claude Code always sets the variable, documented by the verifier.

## Followups

- W2.5: rewrite commands/*.md + agents/*.md paths (crew/scripts/crew.mts -> dist/crew.js, src/scripts/loop.mts -> dist/loop.js; 91+42 refs) and drain the consumer-smoke EXPECTED_FAIL ratchet.
- Extract the shared plugin-root resolver helper used by config-resolver, decisions-store, grade-writer, loop-installer-tokens (reviewer A suggestion); drop the redundant dynamic re-imports in otel-bridge.mts (nit).
- Consider a dist/-aware fallback so dist/loop.js works with CLAUDE_PLUGIN_ROOT unset.

## What went well

The interrupted worktree was recoverable: the builder treated the 54k-line deletion as a symptom, found the collectHookEntries root cause, and locked it with a regression test that provably fails on the old code. Reviewer A ran the real bundle from a clean directory and caught the ENOENT that no test covered; the fix pass widened the audit to seven modules and reviewer B re-derived the reachable-module set from the bundles themselves to confirm no gaps. The verifier exercised every AC against a node_modules-free staged copy, including the Bun-version mismatch path.

## What went wrong

The spec's AC-2 named CLI commands that do not exist, and its import.meta.url audit claim was aspirational; both were corrected in-flight rather than up front. Post-merge dist drift needed an extra rebuild commit on the shared branch.

## What I would do differently next time

Make "run the shipped artifact from a clean directory" a builder self-check before reporting DONE on any packaging slice, and rebuild dist/ as a fixed step of the lane-merge procedure.
