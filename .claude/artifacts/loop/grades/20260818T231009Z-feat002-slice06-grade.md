## Decisions

### DEC-006: package.json node-invoking scripts must flip to bun (SLICE-09)

**Rationale**: .mjs-specifier -> .mts-file resolution is a Bun resolver
feature; plain `node scripts/crew.mts` throws ERR_MODULE_NOT_FOUND. Bun-only
is the decided runtime; the installer:* scripts still say `node`.

**Consequences**:
- positive: one runtime story, matches operator decision
- negative: any residual plain-node consumer breaks until flipped

## Surprises

- Fixing test specifiers UNMASKED a pre-existing production bug: crew.mts's
  own .mjs imports never resolved under node — the stale test paths had been
  404ing before node got that far.

## What went well

All 219 `crew/tests` files renamed cleanly to `.mts` with byte-identical content besides specifiers, reproduced exactly by the reviewer at 954 pass / 148 fail / 100 errors / 116 skip — comfortably above the 846-pass baseline. Stating the target extension explicitly plus a mandatory self-grep (the SLICE-05 fix) worked: zero wrong-extension specifiers this round versus 5 the round before.

## What went wrong

Fixing the stale test specifiers unmasked a pre-existing production bug — `crew.mts`'s own `.mjs` imports never resolved under plain `node`, since the stale test paths had been 404ing before node even got that far, masking the deeper issue.

## What I would do differently next time

Remember that broken-import test files collapse their entire test population into a single fail/error line under bun, so raw suite totals are meaningless while any file still 404s; treat post-fix count increases as newly-unmasked tests running, not regressions.
