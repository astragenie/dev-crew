## Lessons

- **Green unit tests gave false confidence.** The first build's unit tests encoded the same wrong contract as the buggy code (flag read at top-level `config.features` while the block sat under `config.loop.features`). With no integration test exercising the real config path, the suite was green while AC-7 silently failed. Always add one test that drives the actual wiring with a production-shaped input.
- **`console.debug` writes to stdout in Node** (it aliases `console.log`), corrupting any CLI that emits machine-readable JSON. Diagnostics for CLI-reachable modules must go to stderr.
- **Run the canonical `npm test`, not bare `node --test tests/*.mjs`.** `npm test` runs `build:tests` first; calling `node --test` directly ran stale emitted `.mjs` and showed phantom failures from old test bodies. Two minutes lost to a stale-emit red herring.

## Decisions

### DEC-044: feature-toggle config is a top-level `features` block with default-ON resolution

**Rationale**: The object passed to stop-conditions is the full parsed `loop.json`; loop keys read as `config.loop.*`, but `isEnabled` reads the flag at top level (`config.features`). Placing the block under `loop` (first attempt) made the lookup miss → default-ON → gate never disabled. Resolution: keep `features` top-level (sibling of `loop`/`stack`/`reviewers`), and make missing/malformed entries resolve to enabled so config drift can never silently disable a guardrail.

**Consequences**:
- Disabling a gate is explicit and auditable; typos fail safe (stay enabled).
- Each new toggle must register in the `FeatureName` union AND the top-level block — a minor namespacing inconsistency with the `loop.*` keys; documented in `docs/halt-badges.md`.

### DEC-045: diagnostic logging from CLI-reachable modules goes to stderr, never stdout

**Rationale**: `auto` and other subcommands emit JSON on stdout; a debug line on stdout breaks `JSON.parse`. Mirrors the existing `dispatch-trace.mts` stderr convention.

**Consequences**:
- Machine-readable stdout stays clean; observability lines remain visible on stderr.
- No structured logger exists — "debug-level" is conveyed by an `[features]` prefix on a raw stderr write, not a log level.

## What went well

Tight, correct end state: all 7 ACs pass, full suite green (1140/0-fail), docs updated, the magic `1000000` override retired in favor of a clean named toggle. Default-ON design means the change can't accidentally weaken a guardrail. The added AC-4 integration test is exactly the regression guard the slice was missing.

## What went wrong

The specialist layer produced two real defects behind green tests and then paused three times without sealing artifacts, forcing the parent to do the builder/reviewer/validator work inline. That inverted the cost model — a P3, ~0.3-effort slice cost like a large one.

## What I would do differently next time

For a small internal slice with a green-test-but-untested-wiring risk, dispatch the builder with a mandatory "write one integration test that drives the real config object" AC up front, and verify the artifact landed before spending more dispatches — bail to inline after the first pause, not the third.
