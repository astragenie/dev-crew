## Lessons

- Single catch point at the CLI handler is the right layer for audit-logging the refuse-gate. Lower layers (sliceFromFeature) shouldn't take audit-log dependencies; the CLI already owns the dispatcher's `finally`-flush, so the audit batches naturally.
- pm.md edits that change agent behavior need both (a) the rule body and (b) a grep test that pins intent (not exact wording). The grep test anchors on 4 keywords — FEAT-168 citation, `>= 8` threshold, `proposed_slices`, `needs-review` — so future copyediting won't trip the test.
- Skipping crew:lead for sub-30-minute bookkeeping + surgical slices is now a reliable pattern (SLICE-97 + SLICE-98 both inline). For real new-feature work the ladder is still warranted; for "extend existing module + add 2 tests + edit one .md", inline wins.

## Surprises

- Frontmatter parser limitation noted in `feature-lifecycle.mts:282-290` is the real blocker for FEAT-168 AC-4/5 — discovered during slice-a code archaeology, not from the FEAT body. Worth a follow-up FEAT specifically for the parser fix so it doesn't keep blocking downstream work.

## What went well

- Test surface design: spawned the real CLI via `spawnSync("bun", [LOOP_CLI, ...])`. Catches the full path (config resolve, audit-log flush in dispatcher `finally`, exit code) — not just the lib function in isolation.
- Three tests, three distinct surfaces: refuse path, happy path, agent-prompt presence. No test overlap; each one fails for a different production bug.
- Scope discipline: only AC-3 + AC-6 of FEAT-168, deferred AC-4/5 with a recorded reason (parser limit). Resisted the temptation to fix the parser inline.

## What went wrong

- Two LSP diagnostic noise blocks on test imports — spurious (other test files have identical imports and pass tsc). Distracting at the moment they fire. Possible fix: configure LSP to use `tsconfig.test.json` for `src/tests/**`.

## What I would do differently next time

- Recognize the bookkeeping/surgical class earlier and skip crew:lead from the start. Lost ~10 minutes on SLICE-97 dispatching a lead that paused twice. SLICE-98 went straight to inline implementation, ~20 minutes total.
