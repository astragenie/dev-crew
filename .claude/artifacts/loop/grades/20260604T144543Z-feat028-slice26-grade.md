## Lessons

- Test injection seam pattern (from SLICE-25 / backlog-add) ported cleanly to spec-decompose with no surprises. Pattern is reusable; SLICE-D will follow the same shape.
- Architect output parser stayed simple — semicolon-separated string. Tolerating optional parenthetical hints kept the architect prompt flexible without bloating the parser.
- Incomplete-SPEC warn-and-proceed (per FEAT-028 design decision) was the right call — the warn shows up clearly in CLI output; no halt needed.
- Name collision discipline held: dispatched `loop:architect` (the AGENT), never invoked `commands/architect.md` (the CLI). Builder flagged this in their synthesis.

## Decisions

(none new — followed SLICE-23 / SLICE-25 contracts; architect output format is implementation detail, not architectural)

## Surprises

- The existing `spec-decompose` flow already had a clean `featuresOverride` parameter shape — architect output dropped straight in. Less plumbing than expected.
- Architect prompt asks for semicolon-separated output explicitly; if a future architect agent ignores the format instruction and returns structured prose, the parser would treat the whole blob as one feature title. Worth tightening if it ever becomes an issue.

## Followups

- SLICE-D should reuse the same test-injection seam pattern (third site; pattern is well-validated)
- Consider extracting incomplete-SPEC detection into a reusable helper (`isSpecComplete(spec)`) if any other command needs the same check
- If architect output parsing becomes a quality issue, add a stricter format validator + retry-on-malformed pattern

## What went well

Third consumer of `dispatchAgent`; the API surface continues to feel right. Builder caught the `--no-architect` + no-`--features` combination needing explicit helpful error (vs silently exiting zero with empty decomposition) — that's the right defensive shape. Reviewer audit confirmed no regression on existing spec-decompose callers. Audit log accumulates cleanly across three slices now (SLICE-25 researcher entries + SLICE-26 architect entries visible).

## What went wrong

Nothing material. Builder stopped mid-synthesis cleanup but state was correct — no test pollution, all gates green. The mid-message stop is a recurring pattern worth investigating separately (not slice-blocking).

## What I would do differently next time

- Document the architect output format as a contract in the agent prompt itself, not just in the dispatch site.
