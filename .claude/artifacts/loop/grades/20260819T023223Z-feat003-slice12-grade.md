## Decisions

### DEC-012: Validation-artifact writes are fail-hard from now on

**Rationale**: A phase gate that cannot record its verdict must not report
PASS; the old path silently set crewArtifactRegistered:false and continued —
a validation-evidence hole (constitution: validation is its own gate).

**Consequences**:
- positive: validation evidence chain is now trustworthy by construction
- negative: transient artifact-dir problems fail gates that previously "passed" (correct but noisier)

## Surprises

- Plain `git stash` silently drops untracked files — reviewer needed
  stash -u to round-trip the new module; a plain stash would have "verified"
  against half the change.

## What went well

The fail-hard conversion was wired correctly on both the serial and parallel phase-gate paths with no swallowing try/catch, and the reviewer independently reproduced the round-trip sabotage test against the pre-slice code (4 pass / 1 fail) rather than trusting the handoff's report — confirming the fail-hard test genuinely exercises the crew-artifact write path.

## What went wrong

A plain `git stash` during the reviewer's own round-trip verification would have silently dropped the new untracked module, making the verification a no-op; `git stash push -u` was required to actually round-trip against the pre-slice code.

## What I would do differently next time

Default to `git stash -u` (or an equivalent that captures untracked files) whenever a round-trip verification involves a newly-added file, since a plain stash quietly excludes exactly the file most likely to matter.
