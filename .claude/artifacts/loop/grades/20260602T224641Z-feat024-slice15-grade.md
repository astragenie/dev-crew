## Lessons

- Reviewer caught a real flag-parsing bug (repoPath swapped with provider value) that had zero automated test coverage. CLI entry-point scripts need subprocess-level tests, not just smoke checks.
- Separating the library function (`writeTaskStoreConfig`) from the entry-point script (`setup-task-store.mjs`) made the library fully testable; the entry point stayed thin and correct.
- `task-store` alias required one line in COMMANDS — confirms the architecture is easy to extend.

## Decisions

### DEC-003: CLI entry-point flag parsing should be covered by subprocess tests, not manual smoke

**Rationale**: The flag-parsing bug in `setup-task-store.mjs` was caught by the reviewer, not by any automated test. A subprocess-based test (`spawnSync(node, [script, '--provider', 'noop', dir])`) would have caught this before review.

**Consequences**:
- Positive: decision is on record — future setup scripts should include subprocess tests for flag parsing
- Negative: subprocess tests are slower and require temp dirs, but the cost is worth catching real bugs earlier

## Surprises

- `runGithubSubcommand` had `syncPull` and `bootstrapFromGithub` in its destructuring — removing them produced no lint warning. TypeScript silently dropped the unused variables.
- Observability score stayed at 0.65 — the silent NoopProvider fallback from DEC-002 carries over. Pattern is consistent but the gap remains open.

## Followups

- Add subprocess tests for `setup-task-store.mjs` flag parsing in a follow-on.
- Observability gap (DEC-002: unknown provider → silent noop) — address before next provider is added.
- `publishAll` and `syncMilestones` still call github-sync directly — known gap, documented for future Linear FEAT.

## What went well

Library/entry-point separation made the core logic testable without subprocess overhead. Review caught the flag bug efficiently. Entire FEAT-024 (3 slices, 22+ tests, provider interface live) shipped in one session.

## What went wrong

Flag parsing at the entry-point level had no automated test coverage, letting a real bug reach review.

## What I would do differently next time

Write a `subprocess-parse.test.mjs` alongside any new CLI entry-point script. One test per critical flag ordering using `spawnSync` in a temp dir.
