## Lessons

- A flag named `--grade-yaml` set the field expectation that a YAML doc is accepted, but the writer read scores/decisions only from the markdown BODY — the fix is a normalizer that accepts both shapes, not a rename.

## Decisions

### DEC-074: Normalize --grade-yaml input to grade markdown before writeGrade

**Rationale**: writeGrade reads scores via parseScoresFromBody and decisions via parseDecisionsFromBody, both from the markdown body. Rendering frontmatter-only yaml into the template body (rather than a frontmatter fallback in the parser) satisfies AC-1/AC-3/AC-4 in one place and keeps full-markdown inputs byte-identical.

**Consequences**:
- Both the autonomous pure-yaml close path and hand-authored full-markdown grades close identically; no change to the score/decision readers.

## Surprises

- The existing close-slice tests passed the whole time because their fixture was already full grade-markdown (with a `## Scores` list), masking the pure-yaml field bug.

## Followups

- This slice's own close was driven by a pure-yaml grade, exercising the new normalizer end-to-end as live dogfood.
