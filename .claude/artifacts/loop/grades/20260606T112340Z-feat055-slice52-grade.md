## Decisions

### DEC-012: Fail-open semantics for missing aggregate cost report

**Rationale**: Walker must not halt when no aggregate cost reports exist (fresh repos, first-slice scenarios). False halts on bootstrap are worse than missing the gate once. `checkCostRegression` returns `null` when reports directory is empty, when current report has no parseable `usd`, or when `sampleCount === 0`.

**Consequences**:
- positive: bootstrap-safe; new repos do not face spurious halts before first cost report lands
- positive: matches existing fail-open conventions in `slice-cost-ceiling.mts`
- negative: a malformed cost report directory silently disables the gate — no warning; relies on `cost-advise` pipeline staying healthy

### DEC-013: Strict `>` (not `>=`) threshold for halt

**Rationale**: Slice spend exactly at 3× rolling median does NOT halt. Strict greater-than minimizes false halts at the boundary while still catching the 1,802% regression that motivated FEAT-055.

**Consequences**:
- positive: borderline slices proceed; no halt-thrashing at exactly 3× boundary
- negative: a deliberately-tuned 3.0001× regression slips through; mitigated by configurable `costRegressionMultiplier`

### DEC-014: Snapshot field names retain camelCase against contract's snake_case spec

**Rationale**: Contract spec proposed snake_case for `snapshot.costRegression` ("mirror cost-alert reason strings"). Implementation kept camelCase to match existing `snapshot` keys (`sliceCostCeiling`, `gradeTrend`, `iterationCount`, `costAlerts`). Internal-state consistency wins over cross-document mirror.

**Consequences**:
- positive: snapshot remains uniform camelCase across all keys; no inconsistent mixed-case object
- negative: contract artifact diverges from implementation; future readers comparing contract to code will hit the field-naming mismatch — documented here so future maintainers know the choice was deliberate
- followup: contract should be revised on next FEAT-055 slice (if any) to mirror implementation
