## Decisions

### DEC-024: Squash-merge cleanup uses `git branch -D` (not `-d`) after commit verification

**Rationale**: `git merge --squash` followed by `git commit` creates a commit on main with a different sha + tree from the source branch tip. From git perspective the source branch is NOT merged — `git branch -d` refuses with "not fully merged" error. The clean recovery is to verify the squash commit landed on main, then use `-D` to force-delete. This is the standard GitHub squash-merge pattern. Slice file AC-5 was revised in flight to pin this requirement explicitly + Reviewer-A ladder updated to verify the post-commit-verification ordering instead of the original "-d safe" check.

**Consequences**:
- positive: implementation matches reality of squash-merge git semantics; no infinite-retry loop on safe-delete failure; cleanup completes deterministically.
- positive: cleanup ordering (worktree-remove FIRST, branch -D SECOND) prevents the "checked-out branch can't be deleted" failure mode.
- negative: `-D` is genuinely force-delete — if a future refactor moves cleanup to BEFORE squash verification, branch content could be lost silently. Reviewer-A ladder now explicitly tests post-verification ordering.
