## Lessons

- **Consistency bugs live in the gap between two views of the same data.** The walker and the snapshot both rank triaged FEATs, but only the walker filtered `deferred`. The fix was to make the snapshot mirror the walker's existing check (`walker-gates.mts:181`) rather than invent a parallel rule — reuse the canonical predicate so the two can't drift again.
- **Inline was the right call this time.** Single-file filter + 2 tests; dispatching a builder (which paused 3× earlier today) would have cost more than the fix. The repo's `dispatchLimits.preferInlineFor` already sanctions `single-file-edit` for exactly this.

## Decisions

(No new architectural decisions — this slice applies the existing deferred-handling convention from the walker to a second consumer. See DEC from SLICE-41, which moved the deferred check to the shared walker pre-branch filter.)

## Surprises

- Clean run, no specialist-pause this time — because the work was done inline. The contrast with SLICE-87 (3 pauses, $43) underlines the cost of the dispatch pattern for trivial slices until FEAT-176's upstream fix lands.

## Followups

- Consider a shared `isDeferred(frontmatter)` / `isActionable(entry)` helper used by BOTH the walker and the snapshot, so future consumers can't reintroduce this divergence. Not done here (the inline `.filter` is sufficient and low-risk); worth a tiny refactor FEAT if a third consumer appears.

## What went well

Minimal, surgical fix that mirrors an existing pattern; live-verified end to end (FEAT-176 dropped from the real snapshot); full suite green (1145/0-fail); two regression tests pin AC-2/AC-3.

## What went wrong

Nothing material. A self-inflicted detour: redirected `npm test` output to a temp file, which made a polling loop watch the wrong (empty) file and spawn a runaway background task — stopped via TaskStop. Minor process hygiene, no impact on the slice.

## What I would do differently next time

When a fix is a known-pattern one-liner with clear ACs, go inline from the start instead of routing through a dispatch — decide the lane up front based on `preferInlineFor`, not after a pause.
