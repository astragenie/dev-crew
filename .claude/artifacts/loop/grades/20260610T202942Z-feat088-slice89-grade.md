## Lessons

- FEAT-088's core deliverable (convention doc + 3 tagged skills) was already
  shipped under SLICE-07 / SLICE-09. The triage note's "near-exact duplicate of
  FEAT-115" was the live signal — verifying git history before slicing turned a
  would-be-redundant rebuild into a bounded 1-file incremental close.
- For doc-only single-file slices, inline review+validation is the correct,
  proportionate path — the full builder/reviewer/validator ceremony would have
  cost ~3× the actual work, and the specialist-pause pattern (3/5 dispatches
  return no artifact, per learnings digest) makes dispatch actively risky here.

## Decisions

### DEC-046: Rescope FEAT-088 to incremental retrofit, not a duplicate rebuild

**Rationale**: Git history (commit 3d48839 SLICE-07, b1c1800 SLICE-09) showed the
HARD-GATE convention and 3 of the target skills were already tagged. Re-doing
them would burn tokens for zero delta. Scope was narrowed to the one remaining
prominent prose gate (`systematic-debugging`'s Iron Law), reaching the FEAT's
stated "3–5 files" target and legitimately closing it.

**Consequences**:
- positive: no redundant work; FEAT closed with a real (4th-file) improvement.
- positive: pattern reinforced — check `done/` + git log before building any
  "near-exact duplicate"-flagged FEAT.
- negative: slice deliverable is small; most FEAT-088 value predates this slice.

### DEC-047: Inline review + validation for single-file doc slice

**Rationale**: Dispatch budget explicitly prefers inline for single-file-edit.
Specialist-pause pattern is active (learnings digest, confidence 0.9). A 3-line
Markdown tag-wrap does not warrant 3 subagent dispatches.

**Consequences**:
- positive: fast, cheap close ($10.34 vs $16.04 slice median); zero dispatch risk.
- negative: no independent reviewer eyes — mitigated by full automated gates
  (tests 1124/0, content-length, lint) all passing with posted evidence.
