## Decisions

### DEC-005: fs-utils divergent-basename twins merged into .mts, .mjs deleted

**Rationale**: Same-basename .mjs/.mts with divergent exports makes TS bind
specifiers to the wrong twin's types; one canonical .mts restores the repo
convention (.mjs specifier -> .mts file).

**Consequences**:
- positive: TS2305 class eliminated; single source for fs helpers
- negative: any external caller of the deleted real .mjs must re-resolve (none found)

## Surprises

- git show CRLF artifact made one clean rename look like a 366-line diff —
  diff --strip-trailing-cr before believing large rename diffs.

## Followups

## What went well

All 225 non-test production `.ts` files in `crew/` were cleanly renamed to `.mts` with git-detected rename tracking and content diffs limited to import-specifier lines; the fs-utils.mts/mjs divergent-twin merge was verified genuine (not a no-op) and eliminated the TS2305 class of error, with module-resolution proofs and a runtime smoke test both passing clean.

## What went wrong

Parallel batch-rewrite agents drifted on the repo's `.mjs` specifier convention under low effort: 5 import specifiers across 3 files came back as `.mts` instead of `.mjs`, inconsistent even within the same file, only caught by a reviewer grep pass the original AC list wouldn't have run.

## What I would do differently next time

State the exact target extension in fan-out prompts and require a mandatory self-grep before returning — validated directly by SLICE-06, which used this fix and produced zero wrong-extension specifiers versus 5 the round before.
