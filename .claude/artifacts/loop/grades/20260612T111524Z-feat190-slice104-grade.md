## Lessons

- Pure helper extraction (`pickBuilderVariant`) keeps the dispatch logic testable independent of frontmatter IO. The integration tests then verify the wiring via buildDispatchInstruction with inline `sliceContent` strings — no tmp dir setup needed for this layer.
- Interim mapping (fe+be → fullstack) needs explicit test commitment AND a CHANGELOG note. Otherwise SLICE-105 looks like a "fix" instead of a "scheduled refinement".
- Tag-driven dispatch is data-driven routing. The variant choice has zero new branches in legacy modes — the fallthrough branch already exists for `direct-builder`; this slice just makes the agent-name choice variant-aware.

## Surprises

- The `direct-builder` mode still emits `crew:fullstack-dev` regardless of tags. So the only difference between `direct-builder` and `slice-build` on a no-tags slice is the mode label. Worth documenting if we ever consider collapsing them.

## Followups

- SLICE-105 (FEAT-190 slice-2): parallel fanout. Refactor return type to allow `{ parallel: ["frontend", "backend"] }`.
- SLICE-106 (FEAT-190 slice-3): architect pre-flight when `needs_contract: true` AND no contract artifact exists.
- After all three ship: consider deprecating `direct-builder` mode entirely (it's now a strict subset of `slice-build` with `tags: []`).

## What went well

- 13 tests, 4 distinct surfaces (config resolver, pure helper, integration, back-compat). No coupling between tests.
- TSC + lint clean on first run. Two pre-existing-style warnings on duplicated agent-name strings — acceptable, will collapse in SLICE-105.
- CHANGELOG entry documents the interim nature so future readers know SLICE-104 isn't a complete `slice-build` implementation.

## What went wrong
