## Lessons

- **Live demo before file-FEAT works.** Running the parallel-reviewer pattern manually on perf A-1..A-4 commits before authoring FEAT-079 produced concrete artifacts that the FEAT body could cite as evidence. PM scoring + builder context both benefited.
- **Single reviewer caught dead-code yellow in <2 min.** Even on a small diff, the standard `crew:reviewer` dispatch yielded actionable findings fast. Pattern validates for trivial slices.
- **IDE stale diagnostics can mislead.** Initial diagnostics flagged unused symbols and missing node types that were stale. Always re-run `npm run typecheck` + `npm run lint` to verify before trusting IDE diff signal.
- **Reviewer pause-handling SOP still relevant.** Today's earlier test-coverage demo burned 53 tool calls with no artifact. Building the budget-instruction into the multidim preset prompt is the direct response.

## Decisions

### DEC-035: Opt-in via repo config (not per-slice frontmatter)

**Rationale**: `multidim` preset selected via `.claude/loop.json reviewers.ladder.preset` rather than per-slice `review_preset:` frontmatter. Repo-level policy choice; avoids per-slice toggle noise + keeps slice frontmatter focused on slice-specific data.

**Consequences**:
- positive: clean opt-in path; one config edit flips entire repo
- positive: backward-compat — existing repos see zero change
- negative: no per-slice override yet (cannot run multidim on one risky slice without flipping repo-wide); stretch item in FEAT-079

### DEC-036: Scope-fence uses literal "NOT in scope" string

**Rationale**: Every multidim default-focus entry includes the literal substring "NOT in scope" to make the fence grep-discoverable. Enables future validator (or `loop:review-fanout` skill) to assert the fence is present in every generated multidim prompt without LLM judgment.

**Consequences**:
- positive: testable invariant; AC-3 directly asserts the substring
- positive: reviewer agents see consistent fence wording — less LLM ambiguity than paraphrase
- negative: rewording the fence requires updating tests + AC; literal-string brittleness is intentional but not free

## What went well

Live demo of the pattern preceded the FEAT, giving the implementation concrete evidence to cite. Builder produced working preset support with backward-compat + 5 new tests on first pass. Reviewer caught a dead-code yellow within minutes; doc-writer landed CLAUDE.md + CHANGELOG in one pass. End-to-end orchestration (builder → reviewer → validator → doc-writer → final synthesis) completed without help_request escalation.

## What went wrong

Builder emitted a dead-code ternary (`multidim ? "" : ""`) that survived self-verify because lint and tests ignored it. Reviewer caught it but the validator didn't observe the inline fix between artifacts. Cost-regression halt fired in `/loop:auto` mid-day because the upstream competitor-analysis + parallel-reviewer demo burned tokens — required manual override + sequential slice dispatch instead of walker-driven flow.

## What I would do differently next time

1. Pre-commit large research artifacts (competitor analyses, demo runs) before kicking off triage — resets cost-regression baseline so `/loop:auto` doesn't reject the very next slice.
2. Pass reviewer findings into the prompt of the next inline-fix step explicitly, so validator sees the current state rather than re-checking pre-fix evidence.
3. For mechanical fixups inline (single-line dead-code removal), update the review artifact's "Status" field to `resolved` so downstream agents see the fix.
