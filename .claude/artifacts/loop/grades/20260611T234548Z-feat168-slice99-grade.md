## Lessons

- Extracting `consumeBlockArrayItem` and `extendLastArrayMapping` out of `tryConsumeContinuation` kept cyclomatic complexity under the ESLint cap. The pattern (small named helpers, named over inline) survives further extensions if more YAML shapes ever land.
- `isArrayOfMappings([]) === false` is load-bearing — without that guard, an empty `tags: []` would print as `tags:\n` (a null), then re-parse as `null`, breaking every backlog file with empty array fields. The regression test pins this directly.
- Lint regex-spaces rule (`no-regex-spaces`) fires on test assertions that hardcode YAML indentation. Use counted quantifiers `/ {2}/` instead of literal spaces. Cheap to fix; expensive if it bites later.

## Surprises

- Branch order in `serializeFrontmatter` matters: `isArrayOfMappings` MUST come before `isPlainMapping` because `typeof [] === "object"`. Got this right on the first pass but the trap is subtle — anyone refactoring should preserve order.

## Followups

- SLICE-100 (FEAT-168 slice-c): consume `parseProposedSlices(frontmatter.proposed_slices, featureId, effort_points)` in `sliceFromFeature` and materialize all proposed slices atomically (FEAT-168 AC-5). Add idempotent rerun (AC-4) — detect already-materialized slice ids and short-circuit.
- The frontmatter cache (`src/scripts/lib/frontmatter-cache.mts`) was not touched. Should be re-checked when SLICE-100 lands — if it memoizes parse results, the new mapping-array shape needs to invalidate correctly on file modification.

## What went well

- Helpers stayed under 20 lines each; new branches in `tryConsumeContinuation` read top-to-bottom in priority order. No control-flow contortion.
- Tests pin both behavior (parse-only, serialize-only) and identity (round-trip), so a future bug that converts mapping-arrays back to strings breaks 2 tests, not 1.
- Single-edit comment fixup in `feature-lifecycle.mts` keeps the file's reader pointed at the live state (SLICE-100 wire-up pending), not at a since-resolved blocker.

## What went wrong

- One lint error on a hardcoded-indent regex slipped past the local test pass — `bun test` doesn't run lint. Caught at the `bun run lint` gate. Adds ~30 seconds; not a real problem but the lesson is "always run lint before claiming green".

## What I would do differently next time

- Skip writing literal-space regexes in test assertions. `/ {2}/` reads no worse and is lint-proof.
