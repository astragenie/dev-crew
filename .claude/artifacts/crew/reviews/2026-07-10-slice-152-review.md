## Findings

- **[MEDIUM] `moveSlice` drops `moveToNeedsReview`'s pending-dir guard — dormant risk, not yet live.** The old `moveToNeedsReview(slicePath)` (`wave/failure-pivot.mts`, base) was idempotent: `if (!parent.endsWith("pending")) return slicePath;` — it refused to move a slice that wasn't currently in `pending/`. The new `moveSlice(filePath, toState, ...)` (`backlog-store.mts`) has no such guard: it unconditionally computes `targetDir = dirname(dirname(filePath))/<toState>` and moves/unlinks. If `persistPivotAt` is ever wired into `wave/runner.mts` (the design doc explicitly calls this out as future work — `buildPivotsForWave` in `runner.mts:252` currently only calls `buildFailurePivot`, never `persistPivotAt`), a late/duplicate pivot firing after a slice has already progressed to `completed/` would silently move it back to `needs-review/`, which the original guard existed specifically to prevent. Confirmed via grep: `persistPivotAt` has zero production callers today (only `failure-pivot.mts`'s own export and the two test files reference it), so this is not exploitable yet — but it's a real behavior regression relative to the ported function, and neither `wave/failure-pivot.test.mts` nor the new AC-4 regression test in `backlog-store-slices.test.mts` exercises a non-pending source directory. Recommend: either restore an equivalent guard in `moveSlice` (or a `persistPivotAt`-local check) before SLICE-153/whenever `runner.mts` wires it up, or leave a one-line comment on `persistPivotAt` flagging the gap so the future wiring slice doesn't miss it. Not a blocker for SLICE-152 itself since the design doc explicitly scoped semantic-equivalence to "parsed structure," and this guard was never part of AC-4's stated bar — but it should be tracked, not forgotten.

- **[INFO] AC-3 raw-writer sweep confirmed clean.** Zero `fs.writeFile(Sync)?/rename(Sync)?/unlink(Sync)?` against slice files remain in `complete-slice.mts`, `feature-lifecycle.mts`, or `failure-pivot.mts` (the two `fs.writeFile` calls still in `complete-slice.mts` target `feat.filePath` and `gradeFile`, both out of AC-3's slice-file scope). Every other raw-fs hit in `slice-linker/`/`wave/` (`agent-report-writer.mts`, `close-slice.mts`'s grade/state writes, `cost-report-dedup.mts`, `crew-bridge.mts`'s synthesis/handoff artifacts, `slice-progress.mts`'s dashboard) targets non-slice-frontmatter artifacts and is not in scope.
